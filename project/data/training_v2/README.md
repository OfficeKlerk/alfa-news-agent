# Разметка v2 с опорой на проверяемые источники

Это пересмотр 480 AI-оценок из v1, а не независимая экспертная разметка и не
наблюдения финансового ущерба. Исследования помогают выбрать каналы влияния и
ограничить выводы; **оценки 0–3 назначены AI по явно заданной рубрике**. Ни одна
статья не содержит готовых меток для наших компаний. Дата проверки: 22.10.2026.

## Что готово

- Те же 24 новости и 20 профилей из исходных файлов проекта; реальные личности
  компаний и дата наблюдения профилей не подтверждены.
- 8 рецензированных статей, 1 рабочая статья центрального банка, 2 официальных
  методологических материала. Дополнительно сохранены 24 первоисточника новостей.
  У каждой работы указан фактический уровень чтения: полный доступ к нужным
  разделам, рабочая/принятая версия или только аннотация издателя.
- 34 изменения приоритета; 480 записей с источниками, фактами профиля, условиями
  применимости, неизвестными величинами и историей решения.
- 323 записи допущены к предварительному обучению релевантности; 157 отложены.
  Это фильтр качества AI-разметки, а не сертификация правильности.
- 7 условных направлений проверки действий. Их эффективность и финансовый
  результат неизвестны; числа для оптимизатора не выдуманы.
- Исходная v1 сохранена. Обученных весов, демонстрации и новых сетевых зависимостей нет.

## Какие файлы использовать

| Файл | Назначение |
|---|---|
| [EVIDENCE_REVIEW.md](EVIDENCE_REVIEW.md) | Источники, выводы и конкретные изменения |
| [ANNOTATION_GUIDE.md](ANNOTATION_GUIDE.md) | Рубрика, ограничения, экспертная проверка |
| [curation/research_registry.json](curation/research_registry.json) | DOI/URL, метод, выборка, прочитанные разделы, ограничения, кандидаты действий |
| [curation/annotations.jsonl](curation/annotations.jsonl) | Явные пересмотренные оценки; не результат скоринга модели |
| [bundle/eligible.jsonl](bundle/eligible.jsonl) | Допущенные записи всех разделов с сохранённым `dataset_split` |
| [bundle/quarantine.jsonl](bundle/quarantine.jsonl) | Отложенные записи и причины |
| [bundle/revision_log.jsonl](bundle/revision_log.jsonl) | Старый/новый приоритет и причина для каждой пары |
| [bundle/blind_review.jsonl](bundle/blind_review.jsonl) | Шаблон проверки человеком без показанных AI-меток |
| [bundle/audit.json](bundle/audit.json) | Размеры, конфликты признаков и ограничения |

`all.jsonl` и отдельные `train.jsonl`/`test.jsonl` сохраняют **полную** матрицу для
аудита. Для обучения использовать `eligible.jsonl`: CLI и функция `fit` отвергнут
набор с отложенными записями. Фильтрация не переносит примеры между разделами.

| Раздел | Все пары | Допущено | Назначение |
|---|---:|---:|---|
| train | 240 | 187 | Обучение |
| validation | 64 | 19 | Подбор регуляризации; после этого включается в refit |
| test | 80 | 52 | Отложенные события, не используются при fit |
| unseen_company_test | 20 | 12 | Компании, чьи метки не участвовали в fit |
| reserved_company_history | 76 | 53 | История отложенных компаний, не используется при fit |

У validation после фильтра осталось всего **2 события**. Это очень слабая основа
для выбора модели. 480 пар не являются 480 независимыми наблюдениями: решения ЦБ,
индексы ФАО и повторяющиеся компании коррелируют. Выборка целевая, не случайная.
Сравнение с AI-метками измеряет воспроизведение нашей рубрики, а не пользу бизнесу.

## Проверка и воспроизведение

Из корня репозитория, Python 3.11+; сторонние библиотеки не нужны:

```bash
python -m news_analysis.dataset verify --bundle data/training_v2/bundle
python -m unittest discover -s tests -v
```

Сначала собрать SQLite по инструкции `company_context/README.md` из исходных CSV,
оставив `revenue_unit=unknown`. Затем собрать в **новую пустую папку**:

```bash
python -m news_analysis.dataset build --database data/processed/company_context.sqlite --curation data/training_v2/curation --output-dir data/processed/training_v2_rebuilt --holdout-companies U_9917 U_61055 U_35074 U_9948
```

Проверяются хеши исходных CSV, полнота матрицы, ссылки на источники, факты профиля,
правило исключения, неизвестный финансовый эффект, целостность экспорта и разделов.
Проверка кода **не проверяет научную истинность** статьи и не реплицирует её расчёты.
Хеши фиксируют локальные пересказы/данные, а не содержимое удалённой страницы.

Команда для будущего пробного обучения (при подготовке пакета не запускалась):

```bash
python -m news_analysis train --dataset data/training_v2/bundle/eligible.jsonl --model-out data/processed/relevance_v2.json --report-out data/processed/relevance_v2_report.json
```

## Что пока ограничивает модель

Признаки `company_event_v1` сохранены. Они не различают сохранение и изменение
ставки, точный товар, налоговый статус и актуальность повторного сообщения.
Поэтому одинаковые векторы могут иметь разные новые метки; аудит показывает такие
случаи. Улучшение разметки само по себе не устраняет этот предел модели.
Поля `research` — основания целевой метки; нельзя превращать их в признаки, иначе
ответ разметчика попадёт во вход модели. Будущие признаки нужно получать только
из новости и данных, доступных **до** решения.

Для калибровки ущерба и полезности действий нужны реальные исходы и временные
срезы. Схема наблюдений и требования к причинной оценке сохранены в
[v1/ACTION_DATA.md](../training_v1/ACTION_DATA.md). Зарубежные коэффициенты не
подставляются ни в логистическую регрессию, ни в оптимизатор действий.
