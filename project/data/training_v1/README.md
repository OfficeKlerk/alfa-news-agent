# Данные для обучения анализа новостей, версия 1

Подготовлены 480 пар «публикация — профиль компании»: 24 публикации от 8 первоисточников и 20 профилей из исходных CSV проекта, представляющих 13 разделов ОКВЭД. Период публикаций — 12.06.2025–02.10.2026, дата подготовки — 22.10.2026. Модель на этом наборе пока не обучалась.

**Это стартовый корпус с AI-разметкой.** Он пригоден для первых экспериментов с ранжированием и проверки конвейера. Он не является независимым человеческим эталоном, историческим бэктестом или набором наблюдаемых финансовых последствий.

## Что лежит в наборе

| Файл | Содержание |
|---|---|
| `curation/events.json` | Факты в кратком пересказе, даты, первоисточники, структурированные темы и адресаты правил |
| `curation/companies.json` | Выбранные ID и основания выбора |
| `curation/annotations.jsonl` | 480 явных суждений AI: важность, объяснение, канал влияния, недостающие данные, условный следующий шаг |
| `curation/context_snapshot.json` | Хеши исходных CSV: разметку нельзя молча перенести на другой снимок компаний |
| `curation/reason_catalog.json` | Каталог формулировок и оснований меток |
| `bundle/all.jsonl` | Все пары с готовыми 20 признаками, метками, хешами контекста и закреплённым разделением |
| `bundle/profiles.jsonl` | 20 профилей с исходными полями и ссылками на строки CSV |
| `bundle/graph_evidence.jsonl` | Экспозиции платежного графа для каждой пары |
| `bundle/analysis_targets.jsonl` | Структурированные AI-ответы для будущего обучения объяснениям; не измеренные результаты действий |
| `bundle/source_registry.json` | URL, издатель, дата проверки, способ доступа, хеш пересказа |
| `bundle/train.jsonl`, `validation.jsonl`, `test.jsonl` | Основные части набора |
| `bundle/unseen_company_test.jsonl` | Проверка на компаниях, чьи метки исключены из обучения |
| `bundle/reserved_company_history.jsonl` | Остальные примеры этих компаний; не использовать для обучения |
| `bundle/blind_review.jsonl` | Пустые поля для проверки человеком без предложенной AI-метки |
| `bundle/review_queue.jsonl` | Очередь проверки с предложенными метками и причинами сомнения |
| `bundle/audit.json`, `split_manifest.json`, `manifest.json` | Статистика, состав выборок и SHA-256 файлов |
| `action_observation.schema.json`, `ACTION_DATA.md` | Контракт сбора фактических результатов действий предпринимателя |

`jsonl` содержит один JSON-объект на строку, кодировка UTF-8. Для ранжирования входом служит **только `features`**. ID, метки, объяснения, разбиение и предложенные советы нельзя добавлять во входные признаки. Для будущей модели анализа контекст собирается по ID из events, profiles и graph_evidence; целевой ответ берётся отдельно из analysis_targets.

## Откуда данные

Использованы Банк России, ФНС, Правительство РФ, ФАО, Совет ЕС, World Steel Association, Посольство КНР и Государственный Эрмитаж. Музейные сообщения дают отрицательные примеры: совпадение города или страны само по себе не делает новость важной для бизнеса.

20 публикаций проверены чтением страницы первоисточника. Для четырёх использована индексированная выдержка первоисточника: сентябрьское решение ЦБ, июльское ограничение экспорта топлива и два сообщения Эрмитажа. Прямой доступ вернул 403, таймаут или 502; эти записи отмечены для повторной проверки. Полные статьи и изображения не распространяются. Пересказы написаны AI; `excerpt_kind` отличает их от дословных цитат. Права на первоисточники не переобъявляются открытой лицензией.

Факты источника (`sources`) отделены от нашего сопоставления отраслей и адресатов (`semantic_context`, `extraction_origin=ai`). `fact_status=reported` означает, что сообщение приведено как сообщение источника. Оно не подтверждает применимость правила к конкретной компании. Для юридических сюжетов это исторические сообщения, а не проверка действующего права на день будущего использования.

Компании взяты из CSV хакатона, их названия не выдумывались и с реальными юрлицами не сопоставлялись. Подлинность реальных бизнесов за синтетическими ID не установлена. Единицы выручки, валюта и период платежей остаются неизвестными. Профили выбраны целенаправленно: агро, пищевое производство, удобрения и косметика, металл, оборудование, строительство, торговля, перевозки, гостиницы, ПО, недвижимость, медицина. Выборка не репрезентативна; в ней много пользователей финансирования и мало случаев с пропущенными полями.

## Метки и разделение

Правила подробно описаны в [ANNOTATION_GUIDE.md](ANNOTATION_GUIDE.md). Распределение: 0 — 229, 1 — 114, 2 — 135, 3 — 2. Для существующей логистической регрессии положительный класс — `label >= 2`; четыре уровня используются также в NDCG. Уверенность AI — категориальная самооценка, не вероятность правильности.

| Часть | Пар | Компаний | Публикаций |
|---|---:|---:|---:|
| train | 240 | 16 | 15 |
| validation | 64 | 16 | 4 |
| test | 80 | 16 | 5 |
| unseen_company_test | 20 | 4 | 5 |
| reserved_company_history | 76 | 4 | 19 |

Разделение сделано по времени **22 целых групп событий/политик**, примерно 60/20/20. Три публикации о налоговой реформе объединены в одну группу и не разнесены между train и test. Отложенные компании: `U_9917`, `U_61055`, `U_35074`, `U_9948`. Их платежные связи могут присутствовать в исходном графе; это проверка переноса без обучения на их метках, а не полной изоляции графа.

Разные месячные решения по ставке и выпуски индексов остаются коррелированными примерами. 480 пар не равны 480 независимым событиям. На validation и test источники и типы событий представлены неравномерно; выводить из такого малого теста точность всей системы нельзя.

`dataset_split` закреплён в каждой строке. Обучающий код учитывает его, в том числе после импорта частично проверенной разметки, и не пересчитывает границы по оставшимся строкам. Подбор L2 использует validation; финальная модель затем переобучается на train + validation. Обе тестовые выборки остаются вне обучения.

## Запуск

Все команды выполняются из корня репозитория на Python 3.10+, без сторонних пакетов. Готовый `bundle` уже содержит признаки и не требует базы для проверки или обучения.

```bash
python -m news_analysis.dataset verify --bundle data/training_v1/bundle
python -m unittest discover -s tests -q
```

Когда понадобится обучить первый ранжировщик:

```bash
mkdir -p data/processed
python -m news_analysis train \
  --dataset data/training_v1/bundle/all.jsonl \
  --model-out data/processed/relevance-ai-v1.json \
  --report-out data/processed/relevance-ai-v1-report.json
```

Команда выше приведена для будущего запуска. Оценки на AI-метках помечаются `provisional_ai_agreement`: это согласие с разметчиком AI, не доказательство пользы предпринимателю.

Для воспроизведения признаков из исходных CSV:

```bash
python -m company_context build \
  --companies data/appendix_1/df_Uid_data_hack.csv \
  --links data/appendix_1/df_Fid_Uid_link_hack.csv \
  --payments data/appendix_1/df_Uid_payment_hack.csv \
  --database data/processed/context.sqlite
python -m news_analysis.dataset build \
  --database data/processed/context.sqlite \
  --curation data/training_v1/curation \
  --output-dir data/processed/rebuilt-training-v1 \
  --holdout-companies U_9917 U_61055 U_35074 U_9948
python -m news_analysis.dataset verify --bundle data/processed/rebuilt-training-v1
```

Выходная папка сборки должна быть новой или пустой. Хеши исходных CSV должны совпадать с снимком разметки. Время создания SQLite исключено из хеша профиля, поскольку не является датой наблюдения бизнеса.

## Проверка человеком

Для независимой проверки дать человеку только `blind_review.jsonl`, события, профили, граф и инструкцию, скрыв AI-метки и объяснения. Начать со всех 100 пар двух тестов. Не ограничивать независимую оценку только спорными примерами: это исказит метрики. `review_queue.jsonl` служит для исправления разметки с подсказками, а не для слепого теста. В полноценном эталоне желательно два разметчика и разрешение расхождений; сейчас этого не было.

В копии файла заполнить `human_label`, `reviewer_id`, `reviewed_at` с часовым поясом, `reason`, `label_origin="human"`. Сохранить хеши контекста. Импорт:

```bash
python -m news_analysis.dataset import-reviews \
  --bundle data/training_v1/bundle \
  --reviews data/processed/completed-reviews.jsonl \
  --output data/processed/human-reviewed-v1.jsonl
```

Пустые ответы пропускаются, происхождение непроверенных строк не меняется. `review_mode=assisted` честно обозначает просмотр подсказки. Импорт сохраняет `dataset_split`; модель не переобучается автоматически. Для оценки уже обученной AI-модели использовать `news_analysis.ranking.evaluate` на проверенных test-строках. Не подбирать модель по этому результату.

## Что уже выявил аудит

17 групп одинаковых векторов признаков имеют разные оценки важности. Это не повод подогнать метки под признаки: текущий `company_event_v1` не различает достаточно точно товар, адресата нормы и исключения. В `semantic_context` сохранены более точные темы и префиксы ОКВЭД для будущей версии признаков. Эти поля тоже требуют проверки человеком.

11 из 20 признаков постоянны на этой выборке. Здесь нельзя оценить качество обработки новостей о конкретном юрлице, спорных фактов, валютного курса или неизвестной отрасли. События о валютных ограничениях намеренно не названы изменением курса. Нет искусственно испорченных карточек ради разнообразия.

Даты снимков компаний неизвестны. Поэтому каждая новость рассматривается условно как свежая (`as_of=published_at`, freshness=1) относительно одного предоставленного профиля; `query_id` объединяет искусственную корзину для оценки **содержательной релевантности**. Точность времени публикации — день; технически используется конец дня UTC, а не выдуманное точное время. Это не симуляция доступной тогда информации и не обучение старению новостей.

Следующее расширение данных должно добавить независимо размеченные новые события, разные компании с подтверждённой датой снимка, реальные корзины кандидатов и реальные пропуски. Для обучения полезности действий отдельно нужны наблюдения из [ACTION_DATA.md](ACTION_DATA.md). Денежных потерь и эффектов действий в этом корпусе нет.
