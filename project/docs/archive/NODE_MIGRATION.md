Два финальных ответа исчерпали прежний лимит 2600 токенов. Это указывает на возможное обрезание, но finish_reason и текст ответов старой реализацией не сохранялись, поэтому точную причину этого запуска восстановить нельзя.

Исправлено: итоговый JSON получает отдельный настраиваемый лимит LLM_MAX_OUTPUT_TOKENS (по умолчанию 6000); планирование остаётся на 2600. Finish_reason=length/max_tokens теперь вызывает понятную ошибку обрезания без слепой повторной генерации, при этом usage сохраняется. При других ошибках итоговая проверка возвращает конкретные замечания валидатора. Новых платных запросов после исправления не выполнялось.

После исправления: npm test — 16 тестов прошли; npm run build — успешно. Проверки используют подставные ответы, дополнительных платных запросов не было.

## Продолжение проверки: ограничение планирования

После разрешения продолжить тестирование анализ e4e80e587f214a00af8d5409e879de07 остановился на первом запросе: модель исчерпала лимит 2600 токенов при выборе инструментов. Это уже явная ошибка обрезания; автоматического повтора не было. Расход: 1 запрос, 4008 токенов. Общий счётчик после него: 9 запросов, 81 151 токен.

Исправлено: отдельный LLM_MAX_PLANNING_TOKENS, по умолчанию 6000. Итоговый JSON сохраняет отдельный LLM_MAX_OUTPUT_TOKENS=6000. Ошибка указывает нужную настройку для своего этапа. Тест контракта транспорта проверяет разные лимиты планирования и JSON.
