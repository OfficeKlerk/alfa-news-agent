# Архитектура локального прототипа

> Историческое описание Node `/api`. Для текущей Python/Node интеграции `/v1` см. [интеграционный ADR](../integration/ARCHITECTURE.md) и [контракты](../integration/CONTRACTS.md).

Браузер → Express API → SQLite и модули поиска/анализа. В live-режиме сервер обращается к OpenAI-compatible шлюзу организаторов. Runtime — Node.js 24.13+ (24.x), TypeScript; встроенный `node:sqlite` в используемой версии Node помечен experimental.

## Серверные модули

| Файл | Ответственность |
|---|---|
| `server/index.ts` | Запуск, настройки порта, завершение работы |
| `server/config.ts` | `.env`, пути, список моделей и роли |
| `server/app.ts` | HTTP API, валидация входа, очередь задач |
| `server/db.ts` | SQLite, потоковый импорт gzip CSV, профиль и платёжные связи |
| `server/retrieval.ts` | Тематические признаки, ранжирование, поиск по OCR |
| `server/news.ts` | Приём новостей, дедупликация, RSS/Atom |
| `server/agent.ts` | Инструменты агента, кеш, проверка источников, вопросы |
| `server/prompts.ts` | Системный промпт и схема ответа модели |
| `server/llm.ts` | HTTP-клиент, таймаут, локальный лимит и токены |
| `server/types.ts` | Типы данных и ошибки |

SQLite-запросы и расчёты синхронные, HTTP-вызовы модели асинхронные. Для роста нагрузки потребуются отдельные workers/очередь или другой слой хранения. Текущая очередь принимает до 10 задач, одновременно выполняет до двух анализов. После перезапуска незавершённые задачи помечаются ошибкой.

## Данные и поиск

Импорт gzip CSV выполняется потоково в одной транзакции; при ошибке изменения откатываются. Повторный запуск не импортирует CSV заново. База по умолчанию `var/app-node.sqlite3`. Реальные данные, анализы, вопросы и счётчик LLM хранятся локально.

Локальный профиль содержит отрасль, регион, продукты банка, признаки внешней торговли, крупнейших получателей платежей и связи через физлиц. Повторяющиеся карточки пока обрабатываются последней строкой. Суммы используются как исходные значения без неподтверждённых валют и единиц. Самоплатежи пока не исключены из локальных агрегатов.

Лента ранжируется по совпадению тем с отраслью, продуктами, внешнеторговым признаком и отраслями контрагентов. Балл 0–100 — эвристика, не вероятность. Поиск по банковским материалам использует усечённые слова и темы, возвращает OCR-фрагменты со страницей и оригинальной ссылкой. Эмбеддингов и внешнего поиска нет.

## Инструменты и анализ

- `get_company_profile` — профиль выбранной компании. Компания задаётся сервером, а не аргументами инструмента.
- `search_research` — поиск фрагментов аналитики банка в локальном OCR-корпусе.
- `find_related_news` — поиск до трёх похожих событий в сохранённой новостной базе; в интернет не ходит.

Demo выполняет фиксированный план и формирует шаблонный анализ без LLM. Live позволяет модели выбирать инструменты: до четырёх раундов, до шести инструментов в раунде. Если банковский контекст не найден, сервер выполняет дополнительный поиск. Финальный ответ запрашивается в JSON mode и проверяется; предусмотрена одна повторная попытка исправления.

В утверждениях различаются `fact` (факт новости), `bank` (дословная цитата банка) и `ai` (вывод с привязкой к компании и новости). Проверка запрещает неизвестные ID и неподтверждённые банковские цитаты. Она не доказывает смысловую правильность вывода. Риски и действия пока не имеют отдельных связей с источниками. Старые документы дают исторический контекст, а не текущую позицию банка.

Реестр источников включает найденный контекст, даже если он не использован в утверждениях. Trace содержит действия инструментов и результаты проверки, не скрытые рассуждения. Кеш зависит от компании, новости и её текста, роли, режима, модели и версии логики. После изменения корпуса/правил увеличьте `VERSION` или осознанно очистите кеш. Вопросы используют до пяти предыдущих ответов.

## API

Для ленты, анализа, задач и вопросов нужен `X-Company-ID`. POST принимает JSON-объект.

| Метод | Назначение |
|---|---|
| `GET /api/health` | Состояние и версия сервера |
| `GET /api/bootstrap` | Режим, статистика, компании для старта, роли |
| `GET /api/companies?q=…&offset=0` | Поиск компаний, по 30 на страницу |
| `GET /api/companies/{id}` | Профиль компании |
| `GET /api/feed?demo=1` | Персональная лента; `demo=0` скрывает синтетические новости |
| `POST /api/news` | Добавить `{title,text,url}` |
| `POST /api/feeds/refresh` | Загрузить доверенные RSS из настроек |
| `POST /api/analysis` | `{news_id,role,force:false}` → HTTP 202 и `{job_id}` |
| `GET /api/jobs/{id}` | Статус задачи и результат |
| `GET /api/analyses/{id}` | Сохранённый анализ |
| `POST /api/analyses/{id}/questions` | `{question}` → `{answer,source_ids,mode}` |
| `GET /api/research?q=…` | Поиск OCR-фрагментов банка |

Роли: «Финансовый директор», «Генеральный директор», «Руководитель казначейства». Роль влияет на промпт и кеш, но не на ранжирование ленты.

## Безопасность и ограничения

Ключ хранится на сервере. Используются список разрешённых моделей, параметризованный SQL, ограничения входа, same-origin проверка POST, текстовый вывод данных в интерфейсе, CSP и раздача только `frontend/`. Тела ошибок провайдера не возвращаются клиенту. Новостные тексты и документы считаются недоверенными данными; защита от prompt injection частичная.

Перед каждым вызовом модели резервируется локальная попытка. Неудачные запросы тоже учитываются. Лимит сбрасывается в 00:00 МСК и не измеряет рубли или расходы других участников. Общий бюджет организаторов сбрасывается в 03:00 МСК. Запасной шлюз выбирается вручную; автоматического повторного платного запроса к другому адресу нет.

RSS задаются только доверенной серверной конфигурацией. Редиректы, XML entity declarations и потоки больше 2 МБ отклоняются. Произвольного HTTP-поиска, shell и банковских операций у агента нет.

Аутентификация отсутствует: пользователь сам выбирает `X-Company-ID`. Изоляция результатов защищает от случайного смешивания, а не от враждебного клиента. Для внешнего размещения нужны аутентификация, проверка доступа к компаниям, TLS и ограничения нагрузки. Docker публикует порт только на localhost.

## Модуль из командного GitHub

`company_context` — отдельный Python-модуль, не подключённый к этому серверу. Его сильные стороны: сохранение конфликтующих карточек, аудит данных, происхождение признаков, отдельные направления платежей и концентрация контрагентов. JSON-контракт и схема SQLite отличаются от локальных. Подключение требует согласованного адаптера или переноса логики на TypeScript.

## Проверка качества

Автотесты проверяют контракты и сценарии, но не качество настоящей модели. Для содержательной оценки нужны 20–30 пар «компания — новость» и экспертная проверка релевантности, фактов, цитат и полезности действий. Метрики: precision@5, корректность источников, ошибки в цифрах, повторные генерации, задержка и токены. Значения пока не измерены.

Итоговый JSON использует LLM_MAX_OUTPUT_TOKENS (по умолчанию 6000); планирование использует отдельный LLM_MAX_PLANNING_TOKENS (по умолчанию 6000). Finish_reason length/max_tokens вызывает явную ошибку обрезания без автоматического повтора. Неудачный live-тест и результаты проверок описаны в docs/NODE_MIGRATION.md.

## Командные роли и планируемые инструменты

Роли и границы файлов описаны в [TEAM_GUIDE.md](../process/TEAM_GUIDE.md), задачи — в [../TASKS.md](../process/TASKS.md). Матвей — роль 3. В server/retrieval.ts rank/feed относятся к роли 1, research — к роли 3. В db.ts профиль и признаки — роль 1, новости/корпус/индексы — роль 3. Общие app.ts/types.ts и контракты согласовываются с потребителями и ролью 5.

В присланном распределении роли 3 указан FastAPI; локальный стек — Node.js/Express по выбору пользователя. Это предложение для согласования, не утверждённая командой смена технологии. Python не является зависимостью текущего приложения.

search_news и rag_bank_analytics — будущие инструменты из распределения, сейчас их нет. [ROLE_3_BACKEND_RAG.md](../process/ROLE_3_BACKEND_RAG.md) содержит черновик их контракта и этапы реализации. Текущие search_research, find_related_news и GET /api/research продолжают описывать действующий код. Добавление документа не переименовывает инструменты и не добавляет векторный поиск.
