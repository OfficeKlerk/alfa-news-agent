## 4. Смысловые ошибки (самое ценное по скорости)

Все правила — узкие регрессии на дословные тексты REPORT8, не общий семантический верификатор. Каждое закрыто парой «отклонить / пропустить» в `server/integration/tests/tasks8-semantics.test.ts`.

- **null → «отсутствие отметки».** Новая функция `nullMarkRules` (profile-facts.ts) проверяет любой текст, включая conditions и limitations, до пропуска «оговорённых» фраз: «…не доказывает отсутствие обязательств» оговаривает вывод, а не неверную посылку. Отклоняются «null означает отсутствие отметки» (даже внутри «Если…») и «отсутствие отметки / отсутствуют отметки / не отмечены» для продуктов со значением null. Пропускаются: «null не означает отсутствие отметки», «…неизвестны (null), а не отсутствуют», «отсутствие данных об отметке», «если бы…», а также та же фраза при известном false. Отклонение от формулировки TASKS8: простое гипотетическое «Если в снимке отсутствуют отметки…» оставлено разрешённым, потому что это закреплено регрессией REPORT7; определение «null означает…» отклоняется и в условной форме.
- **Отметка продукта → использование или договор.** «использует / пользуется / применяет / обслуживает / привлекает / имеет» + продукт финансирования (кроме «имеет отметку…»). Предпосылка договора: «параметры / условия / стоимость обслуживания / ставки / сроки … действующих (по действующим) кредитов, договоров, обязательств», кроме «наличие…», «если они есть», «при их наличии». «Действующий договор и остаток неизвестны» не отклоняется.
- **Отметка ФТС → деятельность.** «осуществляет / ведёт / занимается / участвует в» + внешнеторговую, внешнеэкономическую деятельность, внешнюю торговлю, ВЭД. В claim «отметка/флаг о внешней торговле, ВЭД, внешнеэкономической деятельности» теперь требует именно `/foreign_trade/has_fts`: путь direction его больше не заменяет. Подсказка repair называет has_fts.
- **Копии правил промпта.** Новое правило `Prompt rule copied into the answer` (добавлено в contracts/diagnostic-rules.json, контракты перегенерированы): «Связь с контрагентом допускает только условный косвенный канал», «не копируй правила» и служебные имена (response_guidance, advice_constraints, industry_wording, profile_path_index, quote_candidates, ai_source_requirements, evidence_layout).

## 2. Strict-маршрут

- Новая настройка `LLM_STRICT_EXTRA_BODY_JSON` передаётся **только** в json_schema-запросах, `LLM_EXTRA_BODY_JSON` — во всех. Поля по умолчанию не заданы: неподтверждённые параметры в платные запросы не попадают. В .env.example — пример в стиле OpenRouter (`provider.order`, `allow_fallbacks`, `require_parameters`), помеченный как неподтверждённый. Секретов в коде нет.
- `LLM_STRICT_MAX_CLAIM_STRING` (не меньше 900, по умолчанию выключено) добавляет `maxLength` к text/quote claims только в provider-схеме. Самая длинная сохранённая дословная цитата — 846 символов, подсказки quote_candidates — до 900.
- Лимит «не больше 3 bank-claims» в схеме по-прежнему не выражен: `maxContains` у провайдеров не подтверждён, а раздельные массивы меняют контракт ответа. Локальная проверка остаётся главной.
- Тест: при ≤3 bank-claims перефразированная цитата всё равно отклоняется (`Quote not found in selected evidence`), четвёртая даёт `Too many bank claims`.
- `response_guidance.quote_candidates` теперь предлагает по одному дословному фрагменту из каждого bank-источника, до 3, с published_at и пометкой об историчности. Раньше был только первый. Промпт велит брать bank-claim из этих кандидатов или как другую непрерывную подстроку того же excerpt.

## 8. Python-тесты

Причина — не данные. В Git для Windows системно включено `core.autocrlf=true` (C:/Program Files/Git/etc/gitconfig). 98 из 103 файлов data/ хранятся в Git с LF, но извлекались с CRLF, и sha256 рабочей копии расходился с манифестами. Проверка: sha256 блоба HEAD для data/training_v2/bundle/all.jsonl = `ebc21b4b…` — ровно значение manifest.json, а рабочий файл с CRLF давал `afe9db41…`. То же для data/personalization/RUBRIC.md.

Исправление: `.gitattributes` с `data/** -text` (данные побайтно как в коммите на любой ОС), а файлы data/ переизвлечены из HEAD побайтно (`git show HEAD:<file>`). Хэши и манифесты не менялись, `git diff` по data/ пуст. `git status` показывает у этих файлов «M» из-за устаревшей stat-информации индекса после смены атрибутов, хотя содержимое идентично. При коммите `.gitattributes` это уйдёт; `git add --renormalize data` ничего не изменит в блобах.

Результат: tests/test_personalization_audit.py и tests/test_research_evidence.py проходят. Полный `pytest tests`: **199 passed, 1 failed**. Падает только `test_weekly_audit_export.py::…symlink_escape`: Windows без режима разработчика не разрешает создавать symlink (`WinError 1314`). Это ограничение среды, не кода. `pytest` по умолчанию (testpaths=tests/integration): **43 passed**. На Windows нужен `PYTHONUTF8=1`: иначе test_payment_contract.py читает фикстуру в cp1251.

## Доработка после REPORT9 (офлайн, промпт v14)

Сделано без платных вызовов. Валидаторы не ослаблены.

- **Strict (п. 2).** Provider-схема strict теперь состоит из трёх типизированных массивов: `fact_claims` (1–2), `bank_claims` (0–3), `ai_claims` (минимум 1, до 3). Всего не больше 8.
