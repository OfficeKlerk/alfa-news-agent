# Сбор новостей и извлечение событий

`server/news.ts` сохраняет публикации; `server/news-events.ts` нормализует даты и
извлекает проверяемые по тексту сведения; `LegacyRetrieval` передаёт события в
общий `/v1`-контур ранжирования. LLM для загрузки и извлечения не вызывается.

## Вход и API

`POST /v1/news` принимает заголовок, текст, HTTP(S)-ссылку и необязательные
`published`/`modified`. Даты допускают ISO с часовым поясом, RSS RFC 2822 с
числовым поясом или GMT/UTC/UT, либо календарную дату `YYYY-MM-DD`.
Ответ содержит `news_id`, `date_status`, `ingestion_status` (`inserted`, `updated`,
`duplicate`), `warnings` и `item` — Event или `null`.
`item=null` означает, что публикация сохранена, но её пока нельзя ранжировать:
например, неизвестна дата, отсутствует ссылка или версия ещё находится в будущем.
Будущая дата изменения также даёт статус `future` и предупреждение
`revision_not_yet_available`, даже если исходная публикация уже была в прошлом.
Этот статус фиксируется на момент сохранения; последующий поиск проверяет
временные границы версии относительно `as_of`, поэтому запись автоматически
становится доступной после наступления её даты без обязательной перезагрузки.

`POST /v1/feeds/refresh` принимает пустой объект и читает только серверный
`NEWS_FEEDS_JSON`. URL из запроса пользователя не принимаются. Счётчики
`inserted`, `updated`, `duplicates`, `quarantined` дополняют совместимые
`processed` и `failed_hosts`; `processed` считает принятые записи, включая дубли.
`quarantined` пересекается с остальными счётчиками, а не является отдельным итогом.
Существуют прежние совместимые `/api/news` и `/api/feeds/refresh`.

## Время и история

- Публикация, изменение и фактическая загрузка хранятся отдельно. Часы загрузки
  никогда не подставляются вместо неизвестной даты публикации.
- У Atom `published` — публикация, `updated` — изменение. Наличие только
  `updated` не подтверждает время исходной публикации.
- Дата без времени имеет точность `day`; для доступности новости используется
  конец указанного дня UTC, `23:59:59.999Z`, с явным предупреждением. Это
  консервативная техническая граница, не восстановленное время публикации.
  Календарные даты решения и вступления в силу обозначаются началом дня UTC;
  это также границы дня, не подтверждённый час юридического действия.
- Невалидные и отсутствующие даты сохраняются для исправления, но исключаются
  из ранжирования. Будущие публикации и версии не попадают в выборку `as_of`.
- При изменении статьи сохраняется предыдущая версия. Если издатель не указал
  корректное более позднее время изменения, новый текст доступен лишь с момента
  его наблюдения. Повторная загрузка не возвращает исправленный текст в прошлое.
  Дата первой известной публикации остаётся прежней и определяет свежесть.
- При совпадении времени нескольких версий выбирается последняя наблюдавшаяся
  допустимая версия. Позднее исправленная будущая версия не становится актуальной
  повторно после наступления её ошибочно указанной даты. Legacy-лента и v1
  используют один механизм выбора версии.
- Банковские документы с отсутствующим/невалидным временем или из будущего
  отсекаются до `top-k`, чтобы не вытеснять доступные документы. Входные поля
  даты читаются в порядке `published_at`, `published`, `date`; результат и
  разрешение ссылки на источник используют одинаковую нормализацию.

Добавляются таблицы `news_metadata` и `news_versions`; исходная таблица `news`
с семью колонками не меняется. Старые записи читаются с нормализацией даты;
при первом обновлении их текст сохраняется как исходная версия. Идентификаторы
источников версии имеют вид `news:<article_id>:<version_id>`. Прежние
`news:<article_id>` поддерживаются с ограничением по `as_of`.

## Дубли и границы извлечения

URL приводится к каноническому виду: удаляются фрагмент и известные tracking
параметры, остальные параметры сохраняются. Без URL используется GUID с областью
конкретной ленты, затем хеш текста. Публикация без HTTP(S)-источника сохраняется,
но не становится реальным событием для анализа.

Разные публикации об одном решении Банка России могут объединяться по
издателю решения, дню, направлению изменения и явно названному итоговому уровню
ключевой ставки. Разные дни, направления и уровни не объединяются. Для прочих
тем объединяются только совпадающие нормализованные заголовок и текст в один
день. Тематическая близость сама по себе дублем не считается. Первое сообщение
определяет свежесть, новые источники добавляют свидетельства. Противоречивые
величины или даты действия помечают событие как `disputed`.
Численно одинаковые уровни `17%` и `17,00%` имеют одну идентичность решения.
Синтетические и реальные сообщения не объединяются.

Правила извлекают решения Банка России по ключевой ставке, явные торговые
ограничения, налоговые сообщения/разъяснения, сообщения о товарных ценах и
индексах, явно указанные целевые коды ОКВЭД и календарные даты действия.
Сохранение ставки отличается от изменения, прогноз — от объявленного решения.
Дельта ставки в процентных пунктах переводится в базисные пункты. Итоговый
уровень ставки и относительное процентное изменение не выдаются за такую дельту.
В контракте `percent` означает относительные проценты; `percentage_points` —
процентные пункты, `bps` — базисные пункты.
Исполнитель действия должен быть прямо связан с глаголом изменения ключевой
ставки: пересказ ЦБ решения другого банка не считается решением ЦБ. Дельта
должна относиться к самой ключевой ставке. Отрицания, опровержения и прогнозы
не превращаются в объявленные изменения. Если статья перечисляет разные
исторические решения, единые направление/дельта/дата остаются неизвестными.

Неизвестные темы остаются `other`, неизвестные детали — `unknown`/`null`.
Автоматического вывода товарных кодов, назначения компании
импортёром по наличию ФТС, сопоставления имён обезличенным ID или доказательства
причинного эффекта нет. При обработке уже размеченного Event правила дополняют
только отсутствующие/неизвестные сведения и не заменяют существующие значения.

Отдельный небольшой словарь `server/news-subjects.ts` сопоставляет явные предметы
сообщения тематическим префиксам ОКВЭД: зерно, удобрения, генерация, размещение,
ИТ, музеи/выставки, нефтяное топливо, электрические сети, автомобильные перевозки,
дорожное хозяйство и водный транспорт. Это вывод классификатора, обозначенный
`subject_okved_codes`, `taxonomy_origin=rule_inference` и версией словаря.
`target_okved_codes` по-прежнему содержит только прямо названные в тексте коды.
Тематический код помогает персонализации, но не подтверждает юридическую
применимость правил и не заявляется как код из первоисточника. Зерновая торговля
46.21 и торговля химическими продуктами 46.75 разделены; весь раздел 46 не
назначается по одному товару. Общее сообщение об основной ставке НДС не сужается
до отрасли из упомянутого в нём частного исключения.
Решение по ключевой ставке не сужается до отраслей второстепенных абзацев о ценах
на топливо, льготах или предприятиях определённого ОКВЭД. Его дата действия
извлекается лишь из фразы, прямо называющей ключевую ставку. Явный церемониальный
заголовок о вручении наград/поздравлении подавляет автоматические тематические
коды из фоновых абзацев. Ручная разметка и явно названные коды не удаляются.
Это ограниченные правила, а не универсальное понимание основной темы статьи.

Каждая извлечённая деталь содержит поле, точный фрагмент входного источника и
ID источников. Проверяются наличие этих ID и вхождение цитаты в каждый источник.
Это проверка связи вывода с переданным текстом, а не независимая проверка
достоверности издателя: RSS-сниппет может быть неполным, а предоставленная AI
парафраза не становится подлинной цитатой первоисточника. Полные статьи по URL
не скачиваются автоматически.

## Проверка

`npm test` включает `news-normalization.test.ts` и `news-ingestion.test.ts`:
даты/часовые пояса, неверные даты, конец дня, Atom, старые записи, ревизии,
ограничения `as_of`, дубли, несколько источников, отрицания, прогнозы и единицы.

Воспроизводимый корпус недели 19–24 октября 2026 собирается
`python3 scripts/fetch_weekly_news.py` из исходных HTML и JSON в игнорируемом
`var/weekly-audit-20261024`. Файл `data/weekly_audit_20261024/sources.json` содержит
только URL, даты, способ получения, длину и хеши. Парсер проверяет дату публикации
и хеш текста; изменение страницы (включая изменяемый URL пресс-релиза ЦБ) требует
повторной проверки снимка. `--fetch` повторно скачивает HTML с проверкой TLS;
NAMEX JSON сохраняется инструментом чтения оригинальной страницы. Полные тексты
не копируются в репозиторий и экспорт. См. журнал
`docs/reports/NEWS_INGESTION_AUDIT_20261024.md`.
