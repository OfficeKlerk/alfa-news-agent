# Интерфейс анализа и оценка качества

## Как пользоваться

После `npm run integration:dev` откройте <http://localhost:8000/analysis/>. В обычном запуске это моки/demo. Для настоящей модели используйте [LIVE_LLM.md](LIVE_LLM.md).

1. Введите ID компании и нажмите «Загрузить» либо выберите ID из списка. Пагинация позволяет пройти всю доступную базу.
2. Выберите новость из ленты, введите свою с источником и датой или импортируйте Event / AnalysisEventRequest / RankRequest JSON, до 100 событий. При импорте RankRequest компания выбирается из JSON; дату анализа и аудиторию задайте в форме.
3. Укажите дату и аудиторию. Нажмите «Подготовить контекст»: модель пока не вызывается. Можно раскрыть полный профиль, ML-оценку и источники.
4. Нажмите «Сформировать ответ». UI отправляет хэш просмотренного контекста; если данные изменились, подготовьте его заново.
5. Прочитайте вывод, основания, условия рекомендаций, недостающие данные и ограничения. Ссылки ведут к переданным источникам, цитаты и поля компании показаны отдельно. Ответ можно скачать в JSON.
6. Задайте уточнение: ответ и его основания появятся под анализом. При смене компании, новости, даты или аудитории предыдущий результат и история очищаются. Запоздалый ответ другого выбора не отображается.

Demo, mock, синтетический контекст и внешний ответ LLM подписаны отдельно. Страница выводит данные через `textContent`, без интерпретации HTML модели; внешние ссылки ограничены HTTP(S), новые окна используют `noopener`. CSP запрещает внешние скрипты. «Прекратить ожидание» отменяет браузерный запрос, но уже отправленный вызов провайдера может завершиться и учитываться в лимите.

`/integration` остаётся техническим стендом, `/learning` — разметкой ML, `/` — исходным Node UI со старым `/api`. Новый пользовательский сценарий работает только через общий gateway `/v1`, не через внутренние порты Python/Node.

## Пять сценариев

Это явно синтетический набор, созданный из контрактных fixtures. Он не является независимым human gold и не содержит настоящих финансовых заключений.

| Сценарий | Что проверяет эксперт |
|---|---|
| `rate_borrower` | Кредит отмечен, но остаток, тип ставки и реальный эффект неизвестны |
| `rate_nonborrower` | Та же новость, кредит не отмечен, депозит отмечен: нельзя копировать вывод о действующем кредите |
| `unrelated_region` | Парк в другом регионе: нельзя выдумывать связь и риск ради заполнения раздела |
| `incomplete_profile` | Наличие кредита неизвестно: нужны вопросы и ограниченная уверенность |
| `no_rag` | Отсутствует банковский материал: нельзя приписывать банку собственный вывод |

## Офлайн-проверка и настоящая LLM

```powershell
npm run llm:evaluate
```

Без флагов используются написанные разработчиком эталонные JSON-ответы; сетевых обращений нет. Отчёт `var/llm-evaluation/offline.json` фиксирует прохождение механических проверок, но оставляет `semantic_review=pending`, оценки `null`, качество внешней LLM — `not_evaluated`. Различие двух эталонов не является доказательством персонализации настоящей модели.

Для локального эксперимента с настроенным ключом:

```powershell
npm run llm:evaluate -- --live
```

Это до 5 запросов, до 10 с исправлением JSON; отчёт — `var/llm-evaluation/live.json`. При первой ошибке прогон останавливается; частичный отчёт сохраняется. Счётчик вызовов эксперимента хранится в отдельной `var/llm-evaluation/calls.sqlite3`; лимит не суммируется автоматически со счётчиком сервиса агента. Синтетические профили не проходят через ML API: для тестирования генерации передаются заранее подготовленные AgentRequest, оценка ранжирования здесь не проводится.

Проверьте каждый реальный ответ. Заполните в JSON `reviewer`, `comparison_review` (сравнение ответов на одну новость для двух компаний) и по каждому критерию `review.<критерий>.score` и `evidence`:

- `company_context`: опора на конкретные и правильно интерпретированные поля компании;
- `causal_reasoning`: обоснованная связь события с бизнесом, без произвольного переноса риска;
- `source_support`: факты и цитаты соответствуют источникам;
- `conditional_actions`: действия имеют условия и данные, которые нужно проверить;
- `uncertainty`: неизвестные величины и отсутствие RAG явно обозначены.

Шкала: 0 — существенная ошибка, 1 — требует исправления, 2 — приемлемо; `evidence` содержит конкретную цитату/поле и пояснение оценки. Затем:

```powershell
npm run llm:evaluate -- --review var/llm-evaluation/live.json
```

Команда требует полный набор из пяти сценариев, повторяет механическую проверку и обнаруживает изменение сохранённого input/analysis по хэшу. Это защита от случайного редактирования, не подпись и не проверка квалификации эксперта. При всех оценках 2 сценарий помечается `accepted_by_reviewer`, иначе `needs_revision`. Автоматический код не ставит оценки за эксперта. Подтверждение офлайн-эталонов не превращает их в оценку внешней LLM.

Для вывода о качестве продукта набор нужно расширить реальными компаниями, независимыми новостями, экспертной разметкой и случаями внедрённых инструкций; оценить несколько запусков и регрессии. Автообучение ML по `/learning` не использует эти ответы и не обучает LLM.
