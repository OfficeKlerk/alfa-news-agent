# Публичный показ без формы входа

Режим явно включается через `AUTH_MODE=public`. Он использует реальные providers и обычные проверки ответа; это не `development` и не mock.

Обязательные параметры gateway:

```dotenv
AUTH_MODE=public
PUBLIC_BASE_URL=https://ваш-домен
PUBLIC_COMPANY_IDS_JSON=["U_4909","U_34911","U_99262"]
AUTH_COOKIE_KEY=случайные_32_байта_в_base64url
INTERNAL_API_TOKEN=отдельный_случайный_внутренний_ключ
```

`PUBLIC_COMPANY_IDS_JSON` — намеренно опубликованные владельцем профили. Список компаний не расширяется из query, заголовка или тела запроса. Личное избранное и вопросы разделяются по гостевым сессиям; браузер получает зашифрованную HttpOnly/Secure/SameSite cookie на семь дней. В другом браузере история другая. Вход и пароль не требуются.

Роли администратора гостю не выдаются, legacy API, импорт/refresh новостей и learning-операции закрыты. Изменения требуют точного Origin. Гость не может выключить общую подписку компании; подбор, вопросы и избранное доступны для разрешённых компаний. Платная генерация всё ещё требует отдельного `ANALYSIS_ENABLED=1` и ключа только в агенте. Суточные квоты сохраняются.

Backend слушает loopback, внешние запросы идут через HTTPS-прокси с сохранением Host. Приватные ML/retrieval/agent не публикуются и требуют INTERNAL_API_TOKEN.

## Воспроизводимый запуск из репозитория

Требуются Docker Compose v2, реальная база company_context из CSV организаторов и HTTPS-прокси. Подготовка данных описана в `company_context/README.md`; маленькие CSV.gz в Git не заменяют полный набор данных. Ключи и реальные CSV в репозиторий не добавляются.

1. Скопировать `config/public.env.example` в приватный `.env.public`.
2. Заполнить `CONTEXT_DB_HOST_PATH` абсолютным путём к существующей SQLite-базе. Пользователь контейнера ML (uid/gid 10001) должен читать файл; достаточно отдельной группы и прав 640, открывать файл для всех не нужно.
3. Указать HTTPS-origin в `PUBLIC_BASE_URL` и осознанно публикуемый список `PUBLIC_COMPANY_IDS_JSON`. `LIVE_COMPANY_IDS_JSON` включает начальные подписки только для тех же компаний.
4. Дважды выполнить следующую команду; разные результаты сохранить в `AUTH_COOKIE_KEY` и `INTERNAL_API_TOKEN`:

```sh
openssl rand -base64 32 | tr '+/' '-_' | tr -d '=\n'
```

5. Для генерации задать приватный `LLM_API_KEY` и `ANALYSIS_ENABLED=1`. Без этого включён сбор, а AI-выводы не подменяются демонстрационными.

```sh
docker compose --env-file .env.public -f compose.public.yaml config --quiet
docker compose --env-file .env.public -f compose.public.yaml up -d --build --wait
```

Проксировать внешний HTTPS на `127.0.0.1:8000`, сохраняя `Host`; `proxy_read_timeout` — 300 секунд. Открывать `/live/`. Health — `/v1/health`; его успех не заменяет проверку реальной новости, AI-ответа и истории. Не выполнять `down --volumes`, если требуется сохранить состояние.

Обычный OIDC-запуск не изменён: для него используется `compose.production.yaml` и `docs/integration/PRODUCTION_ACCESS.md`. Публичный режим не демонстрирует вход реального пользователя через внешний IdP.

На первом сервере код из master хранится отдельно от настроек, данных и Docker-адаптера. Команда `alfa-update` подтягивает master, собирает образы, создаёт закрытую резервную копию состояния и проверяет запуск. Обновление кода не удаляет Docker volumes, базу компаний и ключи. Адрес и серверные пути описаны в переданном владельцу SERVER.md; секретов здесь нет.

В этой ветке также уточнены инструкции качественных вопросов и финансового repair: не повторять ненужные проценты в answer; исходная fact-цитата остаётся в claims. Исправлено узкое ложное срабатывание на просьбы запросить/уточнить параметры договоров. Проверки утверждений о существовании договоров, противоречий флагам и финансовых чисел сохранены и покрыты регрессиями. Версия промпта — `company-news-grounded-v14-public1`, версия исполнения — 2.
