# Evaluate actual bank retrieval and document source-window misses

Прежний BM25-отчёт измерял отдельный Python-скрипт, тогда как агент получает фрагменты от Node-сервиса. Их top-k имеют разный смысл. После восстановления дат нужна воспроизводимая оценка именно действующего поиска.

Добавлена офлайн-команда `npm run rag:evaluate`: настоящий OCR/SQLite/классы serving, 28 запросов, два вида top-k, проверка источников и временной доступности. BM25 reference пересчитывается на том же доступном корпусе. В отчёт включены все 28 запросов и отдельная оценка 26 запросов с доступными целями; недатированное золото не исключается из отчёта молча.

Текущие пять фрагментов находят нужный документ в 22/26 случаях; проекция первых пяти разных документов из top-20 — 26/26. Четыре пропуска связаны с вытеснением ожидаемого документа за первые пять фрагментов. Это диагностическое наблюдение, не уже внедрённое улучшение. BM25 лучше на первой позиции, но пропускает один запрос в top-5 — автоматическая замена ранжирования по этому набору не обоснована.

Serving, API, данные корпуса, промпты и подключения модели не изменяются. Новых зависимостей нет. Добавлены тесты корректности метрик, инструкция, JSON-снимок и отчёт промахов. Проверены typecheck, 121 Node-тестов, build и воспроизведение оценки без сети/LLM.

Проверяющему: [инструкция](../guides/SERVER_RETRIEVAL_EVAL.md), [результаты](../reports/SERVER_RETRIEVAL_EVAL.md). Дальнейший отдельный PR — исследовать разнообразие документов в окне выдачи, затем BM25/гибрид; оценка по страницам требует дополнительной разметки.
