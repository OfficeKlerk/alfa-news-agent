# Передача интерфейса live второму участнику

Ветка: codex/live-ui. База: fe3454a. Изменены только integration/live_ui/*, server/tests/live-ui.test.ts и этот файл. Сервер, API, схемы и расчёты не менялись.

## Подключено к существующему API

- GET /v1/live/status: selection.considered/eligible/queued/scanned_at/items, queue.jobs, subscriptions, generation_enabled, recovery_review_required, collector, budget. Сводка обозначена как последний отбор, очередь и число карточек — показатели компании.
- GET /v1/live/jobs?company_id=...&audience_role=...&limit=100: журнал последних задач. Текущий backend не фильтрует их по роли и не отдаёт audience_role у publicJob; интерфейс явно указывает, что задачи могут относиться к разным ролям. Их статусы не объединяются со статусами отбора выбранной роли. URL восстанавливается из сохранённой карточки или того же news_id в selection, иначе показывается отсутствие ссылки.
- POST /v1/live/subscriptions enabled=false: кнопка «Стоп» останавливает только автоподбор для компании/роли. Очередь, выполняющиеся операции и вопросы не отменяет; это написано рядом с кнопкой и после ответа. Поллинг сохранённых результатов продолжается.
- Вопросы используют прежний POST /v1/live/analyses/:id/questions и GET деталей/задач. Серверный дефект вопросов этой веткой не исправлен.

## Граница работы интерфейса

Журнал — последний снимок отбора и до 100 последних задач, с пагинацией на клиенте. Это не долговечный полный архив проверок. Статус succeeded относится к успешной задаче, selected означает только отбор, а не прохождение всех проверок.

Индикатор показывает только подтверждённые состояния: GET-загрузка, running (подготовка и проверка вместе), queued, deferred, unknown, recovery hold и работа общего collector. Раздельные стадии «отправка модели», «валидация», «публикация» API пока не отдаёт. Таймер имитации этапов не используется.

Сводка обновляется каждые 10 секунд, при возврате на вкладку и после pageshow. При смене компании/роли старые числа очищаются. Новые карточки по-прежнему появляются через кнопку «Новые выводы», чтобы не сдвигать читаемый текст.

## Что требуется от серверной ветки

1. Исправить дополнительные вопросы и проверить цикл от постановки до личной истории.
2. Проверить правильность счётчиков и бюджетов. UI не подтверждает финансовый учёт по данным провайдера.
3. Передавать audience_role и безопасный source_url у задач, фильтровать задачи и показатели по явно согласованной области.
4. Для полного журнала дать отдельное долговечное API с курсором, датами, причинами отбора и результатами проверок. Для детальной анимации — реальные этапы и время их изменения.
5. Если «Стоп» должен прекращать также ожидающие задания, нужен отдельный серверный контракт отмены с сохранением журнала и резервов; уже отправленный платный запрос нельзя считать отменённым или бесплатным.
6. Проверить дедупликацию, роли и все этапы анализа по задачам второго участника.

При сохранении текущих полей ветки совместимы без изменения контрактов. Обновления server API и схем принадлежат второму участнику. Манифест старой поставки delivery-task2 не обновлялся — он уже расходился с master до этой ветки.
