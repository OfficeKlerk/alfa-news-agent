## Найденное и исправленное

Сохранённый отказ провайдера HTTP 429 имел `retryable=true` в публичном описании ошибки. Журнал уже блокировал повторный POST, но клиент получал некорректный сигнал о возможности повтора. Исправлено: безопасный retry локального бюджетного ограничения требует явного `budgetExhausted`; terminal отказ провайдера и неизвестный исход не выдаются за повторяемую ошибку. Полностью полученный/сохранённый provider 5xx теперь также сразу переводит queue job в terminal failed после проверки журнала; отдельный цикл queue retry не требуется. Недоступность/потеря ответа после отправки по-прежнему приводит в unknown, не в «не оплачивалось».

Старая fixture проверки локального лимита уточнена явным признаком pre-send budget exhaustion; новый реальный HTTP-сценарий отдельно проверяет локальный cap и реальный ответ контролируемого провайдера 429. Это не ослабление исходного критерия.

## Что добавлено в перепроверку

- Полный HTTP-agent + очередь: локальный cap → deferred без нового POST; отсутствие ключа → deferred без нового POST; полученный 429/5xx → terminal failed, без повторной оплаты и без retryable.
- Lost repair: два шага уже отправлены, ответ второго потерян; после restart и сверки использованы оба сохранённых шага, третьего POST нет.
- Missing journal после snapshot: без подтверждения оператора отправки нет; разрешение на отправку потребляется один раз и не переносится на следующий неизвестный исход.
- Заново установлены все Node-зависимости из package-lock обычным `npm ci`, без старого node_modules. Попытка установки только из offline-кэша обнаружила отсутствующий tarball; обычная установка завершилась успешно (112 пакетов). Это зависимость окружения, не дефект приложения.
- `TASK3_CONTEXT.md`: самодостаточная инструкция новому аккаунту/устройству, архитектура, scope задач, подготовка, независимые сценарии, внешняя часть и формат отчёта. Не требует старой переписки.
- `scripts/accept_task3.py`: одна команда локальной приёмки с очищенным production-окружением, проверкой исходников, свежими логами, результатами и отдельными NOT_RUN для стенда и экспертной семантики. Сам скрипт не устанавливает зависимости, не включает paid-LLM, collector или deployment.

## Результат

Свежий машинный протокол полного запуска находится в `delivery-task2/reaudit/REPORT.json` и `REPORT.md`, исходные логи лежат рядом. Итоговая база — **476 Node tests, 257 Python tests**, typecheck/build/contracts, bundled news, пять reference-сценариев, банковский retrieval, персонализация и три HTTP smoke-конфигурации. Отчёт runner обязан показывать фактические PASS/FAIL; число в этом документе не заменяет его.

Это **локальная техническая проверка**. Настоящий Qwen, внешний IdP/сервер, инфраструктурное восстановление, суточная нагрузка и человеческая экспертная оценка не выполнялись. В новом контексте это отдельные обязательные этапы задачи 3 с BLOCKED/NOT_RUN до появления входных данных. Код не обещает внешнее exactly-once без поддержки провайдера; unknown требует доказательной сверки либо закрытия без повтора.

Полный проект/изменения коллеги сохранены. В архиве нет секретов, runtime-баз, node_modules или venv. Состав, новый patch к исходному master и контрольные суммы — в `delivery-task2/`. Прежние авторские логи сохранены в `delivery-task2/previous-run/`; актуальный результат — `reaudit/`.
