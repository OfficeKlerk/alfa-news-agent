## 1. Приватность репозитория и данные банка — 🟡 требует владельца
**Проблема:** репозиторий публичный, в нём закоммичены 9 проприетарных PDF-аналитик Альфа-Банка (`data/appendix_2/`) и обезличенные CSV. Проприетарные материалы банка в открытом доступе — риск по условиям кейса.
**Решение:** сделать репозиторий **приватным** и дать доступ жюри `alfa-hack-2026` (ТЗ это прямо разрешает). Переписывать историю git для этого НЕ требуется.
**Исполнитель:** владелец репо (Азат) — только он может сменить видимость.
**Вторично (не под дедлайн):** вынести тяжёлые данные из git, чтобы клон не весил ~177 МБ. Это перезапись истории → меняет commit-хеши и требует переклонирования всеми. Делать только задолго до сдачи.
**Ключ:** проверено — реального API-ключа в истории нет; `.env` не трекается, в `.env.example` ключ пустой. ✅

## 2. Стек: Python vs Node.js — 🟡 предложено
**Контекст:** изначально планировался FastAPI (Python); роль 3 реализовала всё на Node.js/Express/TypeScript. Сейчас оба стека живут параллельно и склеены HTTP-интеграцией (`integration/`, `server/integration/`, `contracts/v1/`). Есть две реализации профиля (`company_context` Python + Node `db.ts`).
**Рекомендация:** **ничего не переписывать. Зафиксировать гибрид через существующий шлюз:**
- Python за `/v1`: роль 1 — профиль + ранжирование/ML (`company_context` + `news_analysis`).
- Node serving-слой: роль 2 (агент), роль 3 (RAG/новости), роль 4 (UI).
- Склейка: `contracts/v1` + gateway (роль 5).
**Условие приёмки решения:** роль 5 подтверждает, что гибрид поднимается зелёным end-to-end (`python scripts/dev.py --native-providers` + Docker). Если стек нестабилен и его никто не ведёт — запасной план: консолидация на Node, Python как reference.
**Со временем:** убрать дублирующий расчёт профиля в Node `db.ts`, оставив его только для legacy `/api`.

## 3. Единица выручки — ✅ рубли
`REVENUE_COMPANY` измеряется **в рублях**. Проверено по распределению: максимум 105,6 млрд ₽; будь это тысячи — одна компания имела бы 105 трлн ₽ (невозможно). База пересобирается с `--revenue-unit rub`; тогда работают `revenue_rub`, `is_large_business` и фильтр крупного бизнеса (>15 млрд). Крупных компаний в наборе — **115**.
