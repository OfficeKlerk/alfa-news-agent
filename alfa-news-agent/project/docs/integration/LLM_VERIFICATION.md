# Повторная проверка комплекта LLM

Подготовка выполнена локально, GitHub не изменён. База кода — интеграция с адаптивным ML; состояние общего master для проверки совместимости — `7c9493bf98c553efc2d9bb2f7f39413bf9774c63`.

## Что исправлено после первой поставки

- Ссылки на источники теперь декодируются в реальный DOM ID, в том числе для `news:...` и `research:...`.
- Пустые строки и строки из пробелов не принимаются как содержательный ответ, ограничения или рекомендации.
- Хэш просмотренного контекста устойчив к порядку ключей JSON и меняется при изменении бизнес-значений. Полный профиль и неизвестные значения сохраняются.
- Дословная фактическая цитата должна присутствовать во всех источниках, указанных именно для этой цитаты.
- Числовой суффикс company ID не служит основанием для финансовой цифры; при проверке литералов учитывается знак числа.
- Параллельный анализ резервирует место сессии до платного вызова. Лимит контекста одинаков для предварительного просмотра и агента.
- pytest создаёт родительскую папку временных данных в чистой копии проекта.
- README сохраняет новые командные ссылки на карту проекта, демо-данные, документы и макет карточки.

## Выполненные проверки

Проверена локальная копия исходников вместе с 27 неизменёнными добавленными файлами текущего master. Общие исходники ML сопоставлены по Git blob SHA; отличий от локальной базы нет. Файлы участников не объединялись автоматически и не заменялись в основном checkout.

- TypeScript typecheck и сборка.
- 57 Node-тестов: контракты, контекст, grounding, ошибки транспорта, параллельность, сессии, вопросы, статическая раздача и состояние UI.
- 36 pytest-проверок: 34 интеграционных и 2 проверки нового командного demo-набора.
- 78 unittest исходных Python-модулей и проверка зафиксированного Python Git-объекта.
- JSON Schema/OpenAPI из единого генератора и пять офлайн-сценариев генерации.
- HTTP smoke с моками и отдельными Node-провайдерами.
- Проверка состава ZIP, совпадения упакованных файлов и списка для коммита.

Результаты запуска настоящего внешнего провайдера не получены: ключ в этой среде отсутствует. Прогон на написанных разработчиком эталонах проверяет программный путь, а не качество реальных ответов LLM. Экспертные оценки в отчёте остаются незаполненными. Визуальный браузерный прогон и Docker в этой среде не выполнялись; HTTP-раздача, SDK и проверки состояния UI покрыты отдельно. Ошибки и ограничения провайдера могут проявиться при первом реальном вызове.
