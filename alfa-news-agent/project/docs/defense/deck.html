Alfa Insight

Превращаем поток новостей в персональные бизнес-инсайты для руководителей крупного бизнеса: что событие значит именно для этой компании, какие риски и возможности, как это оценивает банк.

Проблема

Руководителю важна не новость, а её смысл для его компании

  • У крупного бизнеса уже есть аналитика — нужна интерпретация, а не лента.
  • Значимость события зависит от отрасли, продуктов, контрагентов, региона.
  • Пересказ новостей через ИИ ценности не создаёт — это прямо запрещено в ТЗ.

→ Нужен сервис, который отбирает значимые для конкретной компании события и объясняет их влияние.

Решение

Профиль компании → отбор → интерпретация с источниками

  • Бизнес-контекст из данных: отрасль, продукты банка, граф платежей, ВЭД, регион.
  • Агент (планирование → инструменты → контекст → самопроверка) отбирает и объясняет.
  • RAG по аналитике ЦМИ Альфа-Банка — позиция банка со ссылкой на источник (даты проверены).
  • Разделение факт / позиция банка / вывод AI + трассировка.
  • Валидаторы отклоняют выдуманные числа и недословные цитаты — «красиво, но неправда» не проходит.

Надёжность · почему AI можно доверять

Каждый вывод проверяется — выдумки не проходят

  • Дословные цитаты: факт и позиция банка — только точная цитата источника; число/ставку нельзя «пересказать».
  • Сохранение ставки ≠ шок: режим monitoring_only — модель не выдумывает удорожание, если ставка не менялась (в т.ч. когда эмитент назван общо, «регулятор»).
  • Строгий JSON по схеме: типизированные факт / банк / AI, минимум один обоснованный вывод, пути — только к реальным полям профиля.
  • Самопочинка с диагностикой: до 2 попыток, точная причина отказа доходит до UI; лимит генерации гасит зацикливание без расхода.
  • Свежесть RAG (возраст/разнообразие источников) и сквозная UI/gateway-проверка 15/15 — всё офлайн, без расхода бюджета.
Архитектура

Гибрид Python + Node, связанный контрактами

Данные (CSV/PDF/новости) │ ▼ Python: профиль + ранжирование Node: агент + LLM + RAG + UI (company_context, news_analysis) (server, frontend) └──────── contracts/v1 (JSON Schema + OpenAPI) ────────┘ │ gateway /v1 → интерпретация (факт/банк/AI)

Трассируемость сквозная: provenance профиля → признаки → цитаты с источником. Безопасность AI описана (docs/architecture/SECURITY.md).

Демо · сценарий

Что показываем жюри (5 минут)

  • Компания А (экспортёр) → новость про пошлину: факт, почему важно, риски, честно: по зерну у банка материала нет → вывод AI.
  • Та же новость про ставку у энергетики → низкий приоритет (нет кредитов) — доказательство персонализации.
  • Сохранение ставки → наблюдение (monitoring_only), без выдуманного шока — показать отказ валидатора на выдуманном числе.
  • Trace агента (вызов инструментов) + уточняющий вопрос в чате.

Полный сценарий — docs/guides/DEMO_SCRIPT.md.

Честность · что не доделано

Знаем ограничения — это плюс к доверию

  • Прохождение проверок ≠ смысловая безошибочность — нужна независимая экспертная оценка (пока авто-ревью).
  • RAG пока лексический — вектор поднимет hit@1 (цель-метрика готова).
  • Строгий режим: маршрут провайдера закрепляется у владельца шлюза.
  • Тариф LLM — уточнить у организаторов (механика учёта готова).

Каждый вывод связан с источником; выдуманные числа и переуверенные формулировки отклоняются валидаторами. Где у банка нет материала — не выдумываем, помечаем.
