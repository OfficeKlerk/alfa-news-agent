## Компоненты и ответственность

| Слой | Компонент | Стек | Роль | Делает |
|---|---|---|---|---|
| Данные | `company_context/` | Python | 1 | CSV → SQLite, профиль, граф платежей/связей, сигналы, provenance |
| Данные | `news_analysis/` | Python | 1 | признаки, граф, baseline/ML-ранкер, сценарии, подготовка датасетов |
| Бэкенд | `server/news.ts`, `retrieval.ts` | Node/TS | 3 | загрузка новостей (RSS), RAG-корпус банка, поиск |
| Ядро AI | `server/agent.ts`, `llm.ts`, `prompts.ts` | Node/TS | 2 | агент, инструменты, вызов LLM, проверка, диалог |
| UI | `frontend/` | JS | 4 | интерфейс, лента, карточка, чат |
| Связка | `integration/`, `server/integration/`, `contracts/v1/` | Python+Node | 5 | gateway, адаптеры, JSON Schema/OpenAPI, Docker/CI |

## Контракты — «клей» системы (`contracts/v1`)

Компоненты общаются строго по JSON-схемам (JSON Schema 2020-12 + OpenAPI 3.1). Ключевые:

| Контракт | От кого → кому | Назначение |
|---|---|---|
| `Profile` | роль 1 → 2 | бизнес-контекст компании |
| `RankRequest` → `RankData` | 2 ↔ 1 | отбор/ранжирование событий |
| `SearchRequest`/`RagRequest` → `…Data` | 2 ↔ 3 | новости и аналитика банка |
| `AnalyzeRequest` → `Analysis` | UI/2 | интерпретация (insight) |
| `AgentQuestionRequest` → `Answer` | UI → 2 | уточняющие вопросы |
| `Event`, `Evidence` | 3 → 2/1 | нормализованная новость + источник |

За счёт контрактов роли работают параллельно и заменяемо: любой компонент можно переписать на другом стеке, сохранив HTTP-контракт (напр. RAG роли 3 — хоть Node, хоть FastAPI).

## Гибрид Python + Node — почему так

- Python держит сильные аналитические модули (`company_context`, `news_analysis`: графы, признаки, ML, provenance).
- Node обслуживает агента, RAG-прототип и UI, где уже есть рабочий сквозной сценарий и подтверждённый live-анализ.
- Gateway + `contracts/v1` связывают их по HTTP, ничья работа не выбрасывается.
- Обоснование и условие приёмки решения — `docs/DECISIONS.md`.

## Режимы запуска
- **demo** — синтетические данные и моки, без ключа и расхода бюджета (разработка, CI).
- **live** — реальные вызовы LLM через шлюз, ключ только в локальном `.env`.
Смешение demo/live запрещено (не подменять live на demo незаметно — отражено в задачах роли 4/5).

## Трассируемость (сквозная)
Каждый вывод восстановим до источника: `provenance` в профиле (SHA-256 файлов, номера записей) → признаки/граф в ранжировании → цитаты с источником в интерпретации → `trace` шагов агента. Это обеспечивает критерий №11.
