# Оценка RAG-ретрива по корпусу банка (baseline)

> Это отдельный BM25 reference на полном корпусе, не качество рабочего Node-сервиса. Актуальная оценка serving с датами, теми же доступными документами и отдельными единицами top-k: [SERVER_RETRIEVAL_EVAL.md](SERVER_RETRIEVAL_EVAL.md).

> Реальный прогон: лексический BM25-ретривер (`rag_reference_retriever.py`) над OCR-корпусом аналитики ЦМИ Альфа-Банка (`data/research.json`, 64 страницы / 9 документов), оценён на **28 размеченных запросах** (`queries.json`). Закрывает пробел `docs/reports/MONITORING.md` («retrieval hit-rate»). Это baseline — нижняя планка для векторного/гибридного поиска роли 3 (R3-05).

## Результат (28 запросов)

| k | hit@k | recall@k | MRR |
|---|---|---|---|
| 1 | 0.54 | 0.48 | 0.723 |
| **3** | **0.93** | **0.84** | 0.723 |
| 5 | 0.96 | 0.95 | 0.723 |

Метрика устойчива при расширении набора с 12 до 28 запросов (hit@3 ≈ 0.92→0.93), вывод тот же.

- **hit@k** — доля запросов, где хотя бы один нужный документ попал в топ-k.
- **recall@k** — доля нужных документов, найденных в топ-k.
- **MRR** — средний обратный ранг первого нужного документа.

## Что показал baseline (зачем нужен векторный поиск)

Лексический BM25 уверенно находит нужный документ в топ-5 в 96% запросов, но **часто ошибается на 1-м месте** (hit@1 всего 0.54). Конкретные провалы:

- **q01 «решение ЦБ по ключевой ставке 14%»** → на 1-м месте `Gold_digest` вместо `Policy_Rate` (нужный — только #2). Причина: слово «ставка»/числа встречаются и в обзоре золота.
- **q02 «жёсткая риторика регулятора»** → `Gold_digest` #1, `Policy_Rate` только #3.

Это типичные ошибки лексики: совпадение слов без учёта смысла. **Векторный/гибридный поиск (R3-05) должен поднять hit@1 и hit@3** — и измеряется он этим же харнессом.

## Как воспроизвести

```bash
python scripts/rag_reference_retriever.py --corpus data/research.json \
  --queries data/demo/rag/queries.json --out data/demo/rag/reference_retrieval.json --k 5
python scripts/evaluate_retrieval.py --queries data/demo/rag/queries.json \
  --retrieval data/demo/rag/reference_retrieval.json --k 3
```

Для оценки векторного поиска: привести его выход к формату `reference_retrieval.json` (`{queries:{qid:[{filename,...}]}}`) и прогнать `evaluate_retrieval.py` — сравнение честное, набор запросов тот же.

## Честные оговорки
- Набор 28 запросов — демонстрационный; разметка «запрос → документ» сделана по теме содержимого, для защиты стоит расширить и проверить вторым человеком.
- Оценка — на уровне документа (не чанка/страницы). Для цитат на странице нужна отдельная метрика page-level.
- BM25 — reference baseline, не продакшен-поиск.
