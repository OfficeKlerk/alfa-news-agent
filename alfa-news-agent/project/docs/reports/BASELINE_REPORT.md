# Baseline-метрика ранжирования (реальный прогон)

> Это **настоящая** метрика: ранжировщик `news_analysis.analyze_news` (baseline, без обученной модели) прогнан на демо-наборе (`demo_news.json`) для трёх демо-компаний, результат сравнён с ручной разметкой (`labels.json`). Не заглушка. Закрывает R1-02 («воспроизводимые метрики baseline»).

## Результат

| Метрика (k=3) | Значение |
|---|---|
| **nDCG@3 (macro)** | **0.9717** |
| **precision@3 (macro)** | **0.8889** |
| nDCG@5 (macro) | 0.9526 |
| precision@5 (macro) | 0.60 |

По компаниям (k=3):

| Компания | precision@3 | nDCG@3 | Комментарий |
|---|---|---|---|
| U_34911 (зерно) | 1.00 | 0.9152 | порядок неидеален — см. ниже |
| U_99262 (дороги) | 1.00 | 1.00 | топ-3 все высокорелевантны |
| U_4909 (энергетика) | 0.667 | 1.00 | порядок верный; 1 слабая новость в топ-3 |

## Что показал baseline (инсайт для доработки)

У U_34911 baseline поставил «ЦБ сохранил ставку» (релевантность 2) **выше** профильных «пошлина на зерно» и «ослабление рубля» (релевантность 3). Причина: правило сигнала «ключевая ставка» имеет вес 0.9 и **перебивает** более специфичные для экспортёра торговые сигналы (0.8).

→ **Направление улучшения (R1-03):** снизить доминирование общего сигнала ставки относительно профильных ВЭД-сигналов, либо ввести ML-реранкинг на размеченных парах. Метрика выше — отправная точка, по которой можно измерить эффект.

## Важные оговорки (честность для защиты)

- **Разметка пока не независима.** `labels.json` составлена с опорой на ту же логику сигналов, что и ранжировщик → метрика завышена. Для защищаемого числа нужна **независимая человеческая разметка** (см. инструкцию по разметке). Текущее значение — ориентир, не финальный результат.
- Набор маленький (3 компании × 6 новостей = 18 пар) — демонстрационный, не статистически значимый.
- Новости синтетические (`is_mock`). На реальных новостях метрику нужно перепроверить.
- `score_kind = manual_feature_baseline` — это не обученная модель и не вероятность ущерба.

## Связь с обученным ранкером (в master появился)

В master есть адаптивное обучение ранжировщика (попарный logistic, `docs/integration/ADAPTIVE_LEARNING.md`). Baseline из этого отчёта — **точка отсчёта**: обученную модель оценивают той же метрикой (nDCG), и допускают только при приросте над baseline на независимом gate-наборе. То есть число ниже — это нижняя планка, относительно которой измеряется польза обучения.

## Как воспроизвести

```bash
# 1) собрать базу (из корня репо)
python -m company_context build \
  --companies data/appendix_1/df_Uid_data_hack.csv \
  --links data/appendix_1/df_Fid_Uid_link_hack.csv \
  --payments data/appendix_1/df_Uid_payment_hack.csv \
  --database var/context-real.sqlite3 --revenue-unit rub

# 2) получить реальные предсказания ранжировщика (скрипт в PR: scripts/run_baseline_ranking.py)
python scripts/run_baseline_ranking.py --database var/context-real.sqlite3 \
  --news data/demo/demo_news.json --out data/demo/eval/baseline_predictions.json

# 3) измерить
python scripts/evaluate_ranking.py \
  --labels data/demo/eval/labels.json \
  --predictions data/demo/eval/baseline_predictions.json --k 3
```

Файлы результата: `baseline_predictions.json` (порядок новостей на компанию), `baseline_scores.json` (сырые score).
