# Проверка ранжирования и условных советов — 24 октября 2026

Проверены Python-расчёт `analyze_news`, признаки v1/v2, граф платежей,
`conditional_advice`, сценарный оптимизатор и локальное обучение. Внешняя LLM
не использовалась. Исправления не подбирают коэффициенты под недельную подборку
или под прежние 39 оценок персонализации. Обучение на новых метках не запускалось.

Это отчёт о поведении расчётного модуля. Регрессионные тесты ниже используют
синтетические входы и проверяют конкретные ошибки; они не подтверждают качество
извлечения реальных новостей или качество советов для предпринимателей.

## Что означают результаты

| Поле | Что оно действительно показывает | Чего оно не показывает |
|---|---|---|
| `score`, `score_kind=manual_feature_baseline` | Приоритет внимания по ручным весам совпадений, давности, статуса события и другим признакам | Вероятность ущерба, размер потерь, экспертную важность по шкале 0–3 |
| `score_kind=logistic_relevance_uncalibrated` | Неоткалиброванный балл обученной модели релевантности | Подтверждённую вероятность события или финансового ущерба |
| `facts.fact_status` | Переданный статус сообщения; спорность отдельно влияет на приоритет проверки | Независимую проверку факта самим Python-модулем |
| `graph.in/out.matched_share` | Долю наблюдаемых платежей контрагентам с совпавшими атрибутами | Долю убытка, причинную зависимость, роль покупателя/поставщика, валютную экспозицию |
| `scenario` | Условный расчёт по явно предоставленной экспозиции, шокам и параметрам действий | Обученный причинный эффект действий, наблюдаемый результат новости |
| `conditional_advice` | Вопросы для проверки и направления сравнения при выполнении условий | Команду заключить сделку, изменить цены или обещание финансового результата |

Ручной балл не ограничен диапазоном 0–1: его нельзя показывать как проценты.
Достоверность новости и величина влияния должны оставаться отдельными полями.
Сохранение ставки может быть значимым контекстом, но не задаёт новый шок ставки.
`null` в продуктах, роли или графе сохраняется как неизвестность, а не как ноль
финансовой экспозиции или подтверждённое отсутствие операции.

## Найденные и исправленные ошибки

| Случай | Предыдущее поведение | Исправление |
|---|---|---|
| Ключевая ставка сохранена | Общий совет предлагал сравнить защиту финансирования от изменения | `monitoring_only`: проверить действующие договоры и даты пересмотра, не приписывать новости новый шок |
| Ставка сохранена, а продукты отсутствуют или неизвестны | Совет подразумевал наличие кредитов и депозитов у любой компании | Упоминаются только отмеченные продукты; неизвестность отделена от явных `false`; при отсутствии продуктов предлагается наблюдение без проверки выдуманных договоров |
| Только свежесть или покрытие графа без совпадений | Даже несвязанная новость порождала предложение проверить операции и договоры | `no_confirmed_link`: нет операционного действия без наблюдаемого бизнес-канала; отсутствие связи в данных не объявляется доказанным отсутствием влияния |
| Подтверждённая дата действия и совпадение по профилю/графу | Общий совет не использовал известную дату | `conditional_timing_check`: сверить применимость документа и график операций с датой; совпадение не доказывает юридическую обязанность |
| В профиле одновременно кредит и депозит | Возвращался только первый совет о финансировании | Сохраняются оба условных направления, со своими недостающими параметрами |
| Снижение ставки у компании с финансированием | Общая формулировка о защите не учитывала направление | Предлагается проверить возможность снижения договорной стоимости и комиссии, без обещания автоматического снижения |
| Прогноз, спорное сообщение или неизвестное направление ставки | Тип события мог приводить к обычному финансовому совету | Отдельные статусы `scenario_only`, `source_verification`, `needs_event_details`; сначала подтверждаются факты |
| Известное несовпадение узкой отрасли или роли | Совет оставался общим для типа новости | `applicability_check`; при наличии только косвенной связи — `indirect_exposure_check`, без переноса требований контрагента на компанию |
| Старый артефакт v1 и новые уточнения применимости | Новые проверки советов могли зависеть от версии ранжировщика | Числа v1 остаются прежними; применимость советов проверяется текущими правилами отдельно |
| `direction=unchanged` при ненулевой величине или изменение при величине 0 | Противоречивый набор признаков принимался | Такой контракт отклоняется; отсутствующая величина остаётся допустимым неизвестным значением |
| Повторяющиеся ID источников | Ссылки на цитаты могли неоднозначно привязываться к содержимому | Дубли ID отклоняются; старые источники без ID поддержаны как отдельный случай совместимости |
| Граф одной версии передан признакам другой | Совпадения разных определений могли смешаться молча | Явно несовместимый `method` отклоняется; проверяется диапазон долей 0–1 |
| Переполнение в дополнительном, не базовом шоке | Итоговый базовый показатель мог быть конечным, а другой сценарий содержать NaN/Infinity | Проверяются все числовые поля каждого исхода до возврата результата |
| Пустой или неправильный тип долей действий | Возможна низкоуровневая ошибка вместо проверки входа | `evaluate_plan` требует объект долей и возвращает понятную ошибку валидации |
| Аналитика банка опубликована после `as_of` | Самостоятельный Python-вход не проверял её дату | Будущий фрагмент отклоняется; отсутствующая дата явно отмечается предупреждением |
| Большая первая компания в pairwise-обучении | Первые 5000 пар могли исчерпать бюджет до остальных компаний | Пары выбираются по очереди из информативных запросов; записывается число участвующих запросов |

В pairwise-обучении сохранены функция потерь и лимит 5000 пар. Если самих
информативных запросов больше лимита, необходима явная разбивка. Ограниченная
выборка пар не объявляется статистически несмещённой или доказательством качества
для всех компаний; прежние контрольные проверки продвижения модели сохраняются.

## Сценарии и нулевой эффект

Проверено, что нулевая экспозиция или нулевой шок приводят к отсутствию действий,
в том числе при бесплатных действиях. Сохраняются проверки бюджета, ликвидности,
суммы долей, доступности действий, задержки и отрицательных шоков. В результате
добавлен `decision_reason`, поясняющий выбор бездействия или положительной условной
экономии. Отсутствующие параметры не заменяются выдуманными суммами или эффектами.

Вручную предоставленный сценарий допускается и рядом с новостью о сохранении
ставки: это может быть самостоятельный стресс-сценарий. Теперь карточка явно
предупреждает `scenario_is_conditional_not_observed_event_loss` и, для сохранения
ставки, `unchanged_rate_does_not_supply_a_new_rate_shock`. Числа такого сценария
не выводятся из новости, доли платежей или бинарного признака кредита.

## Прогон реальной недельной подборки

Для новостей 19–24 октября 2026 года следует использовать тот же рабочий путь,
без заглушек и без генератора LLM:

```python
from company_context import ContextStore
from news_analysis import analyze_news

with ContextStore(database_path) as store:
    result = analyze_news(
        store, company_id, events, as_of,
        model=None, cases=(), bank_analytics=(),
        limit=min(100, len(events)), feature_version="company_event_v2",
    )
```

Сохраняются исходные цитаты, даты, профиль, граф, вклады признаков, статус факта,
условные советы и предупреждения. При пустом `cases` финансовый эффект остаётся
`not_requested`, а не оценивается скрытой формулой. Датированные версии источников
должны быть доступны не позже `as_of`; полный профиль берётся из исходной базы,
а не из небольшой синтетической базы CI. Проверка реальных недельных карточек
должна фиксироваться отдельно от результатов приведённых unit-тестов.

## Оставшиеся ограничения

- Тематические ОКВЭД — вывод правил, не юридическое доказательство применимости.
- Страны ФТС не подтверждают резидентство, направление торговли, наличные
  валютные операции или конкретные импортируемые товары.
- Размер платежа без валюты, периода и роли не превращается в сумму риска.
- Признаки профиля не содержат подтверждённых условий плавающей ставки,
  даты пересмотра, открытой валютной позиции или эффекта конкретного действия.
- Ручные веса и AI-разметка не заменяют независимую проверку предпринимателем
  или предметным специалистом. Высокий балл ещё не доказывает полезность совета.
