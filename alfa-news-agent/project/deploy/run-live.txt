ОБНОВЛЕНИЕ ПОСЛЕ ОБЪЕДИНЕНИЯ: live теперь требует OIDC/секреты/HTTPS proxy. Актуальные условия — deploy/MERGED_RELEASE.md. Ниже сохранена исходная инструкция коллеги.

ЛОКАЛЬНЫЙ СЕРВИС НОВОСТЕЙ И ПЕРСОНАЛЬНЫХ ВЫВОДОВ

Требуются macOS/Linux, Node.js 24.13–24.x, Python 3.12+ и существующая база company_context.
Команды выполняются из корня проекта. База компаний подключается только для чтения.

Установка:

npm ci
npm run build
python3 -m venv .venv
.venv/bin/pip install -r requirements-integration.txt -c requirements.lock
cp config/live.env.example .env.live

Проверка конфигурации и базы без внешних HTTP-запросов:

.venv/bin/python scripts/live.py --context-db /absolute/path/companies.sqlite --env-file .env.live --check

Запуск:

.venv/bin/python scripts/live.py --context-db /absolute/path/companies.sqlite --env-file .env.live

Интерфейс персональной ленты: http://127.0.0.1:8000/live/

Выберите компании в интерфейсе. Для стартового списка можно задать в личном env:
LIVE_COMPANY_IDS_JSON='["U_34911","U_99262","U_4909"]'
Идентификаторы должны существовать в подключённой базе. Ограничение количества
подписок задаётся LIVE_MAX_COMPANIES. Не следует анализировать всю базу компаний
без предварительного расчёта ресурсов и квот.

СБОР И ОБРАБОТКА

Начальная конфигурация содержит 13 адресов источников на 12 доменах: Банк России,
ФНС, Минтранс, ТАСС, Интерфакс, Коммерсантъ, Гарант, Парламентская газета, Прайм,
Лента.ру, Финам и Агроинвестор. Реестр адаптеров находится в
config/news-source-registry.json; список адресов — в config/news-sources.json.
Локальный runner читает этот список, если NEWS_FEEDS_JSON не задан. Явный пустой
массив является ошибкой. Допускается до 64 различных HTTPS-адресов.

Ленты и страницы проверяются каждые NEWS_POLL_SECONDS (по умолчанию 300).
NEWS_SOURCE_CONCURRENCY ограничивает одновременно опрашиваемые источники.
Получение полного текста включено. NEWS_FULL_TEXT_CONCURRENCY ограничивает
параллельные загрузки статей; NEWS_FULL_TEXT_MAX_PER_SOURCE — количество загрузок
на источник за цикл; NEWS_FULL_TEXT_REFRESH_SECONDS — интервал перепроверки текста.
Блокировки издателей и robots.txt не обходятся. Если полного текста нет, публикация
сохраняется с доступным анонсом и явным статусом/причиной неполного текста.
Сбой одного источника не останавливает остальные; ошибки и время успеха видны в статусе.

LIVE_SCAN_SECONDS задаёт интервал персонального отбора, LIVE_LOOKBACK_DAYS — глубину
поиска, LIVE_MAX_CANDIDATES — предел кандидатов, LIVE_COMPANY_NEWS_LIMIT — число
новостей на компанию за сутки с учётом незавершённых задач. Существенные исправления
уже отобранных статей ставятся отдельно; общий LLM-бюджет остаётся ограничен. LIVE_WORKER_CONCURRENCY ограничивает одновременные
фоновые задачи. Worker выполняется внутри gateway; это один из четырёх процессов,
отдельный пятый процесс не нужен. Очередь и результаты сохраняются в SQLite.

БЕЗ КЛЮЧА И С КЛЮЧОМ

Без ключа продолжаются сбор, персональный отбор и сохранение очереди.
Генерация откладывается; выдуманные ответы вместо Qwen не публикуются.
После получения ключа заполните только личный .env.live:

LLM_API_KEY=<ключ вашего провайдера>
LLM_BASE_URL=https://changellenge.up.railway.app/v1
LLM_MODEL=qwen/qwen3.6-35b-a3b

Адрес и модель должны соответствовать договорённостям с провайдером.
Для включения платных вызовов остановите предыдущий runner и запустите:

.venv/bin/python scripts/live.py --context-db /absolute/path/companies.sqlite --env-file .env.live --with-llm

Само наличие ключа не включает платные вызовы: обязателен флаг --with-llm.
Ключ получает только процесс agent. Env-файл нельзя добавлять в Git или архив.
Переменные shell имеют приоритет над файлом.

БЮДЖЕТ

MAX_DAILY_LLM_CALLS и MAX_DAILY_LLM_TOKENS ограничивают общие вызовы и токены за сутки.
MAX_COMPANY_DAILY_LLM_CALLS задаёт дневную квоту компании.
LLM_QUESTION_RESERVE_CALLS и LLM_QUESTION_RESERVE_TOKENS оставляют долю для вопросов.
Каждая попытка исправления ответа расходует отдельный вызов. Общий счётчик хранится
в agent.sqlite3 и обновляется атомарно. При неизвестном usage, тайм-ауте или падении
полный резерв запроса сохраняется: отсутствие ответа не доказывает отсутствие оплаты.
Это квоты вызовов и токенов, а не подтверждённая стоимость в рублях или долларах.
Сброс в 00:00 МСК. При исчерпании квоты сбор продолжается, генерация откладывается.

ПРОЦЕССЫ, СОСТОЯНИЕ И ВОССТАНОВЛЕНИЕ

Четыре процесса: gateway/worker :8000, Python ML :8101, retrieval/collector :8102,
agent :8202. Все локальные порты слушают 127.0.0.1. Изменить их можно через PORT,
ML_PORT, RETRIEVAL_PORT, AGENT_PORT. Runner не завершает чужие процессы на занятых портах.

Постоянные базы и журналы: var/integration/live-news (можно выбрать --state-dir).
Файлы gateway.sqlite3, retrieval.sqlite3 и agent.sqlite3 сохраняют соответствующее
состояние между запусками. Не удаляйте SQLite, WAL и SHM-файлы работающего сервиса.
Два runner не могут одновременно использовать один каталог состояния.

Supervisor перезапускает упавший дочерний процесс с задержкой 1…60 секунд.
Задержка растёт после повторных сбоев и сбрасывается после устойчивой работы.
Если порт занял другой процесс, supervisor сообщает проблему и ждёт; он его не убивает.
Статус supervisor: var/integration/live-news/supervisor-status.json.
Журнал supervisor: var/integration/live-news/supervisor.log; отдельные процессы пишут
в gateway.log, retrieval.log, agent.log и ml.log. В статусе нет ключей или env.

Ctrl+C сначала останавливает gateway/worker при ещё работающих зависимостях, затем
agent, retrieval и ML. LIVE_SHUTDOWN_GRACE_SECONDS задаёт время на завершение каждого
процесса (по умолчанию 30 секунд). После принудительной остановки незавершённые задачи
восстанавливаются по сроку аренды; базы не сбрасываются.

Для другого экземпляра нужны отдельный --state-dir и другие четыре порта.
Пример:
PORT=8300 ML_PORT=8301 RETRIEVAL_PORT=8302 AGENT_PORT=8303 .venv/bin/python scripts/live.py --context-db ../companies.sqlite --state-dir var/integration/second --env-file .env.live

DOCKER COMPOSE ДЛЯ ПЕРЕНОСА

В .env.live заполните CONTEXT_DB_HOST_PATH абсолютным путём к существующей базе.
NEWS_FEEDS_JSON в Compose обязателен; готовый список находится в примере env.
Оставьте ANALYSIS_ENABLED=0 до появления ключа. Для платной генерации задайте
ANALYSIS_ENABLED=1 и LLM_API_KEY. Внешний порт задаётся GATEWAY_PORT.

docker compose --env-file .env.live -f compose.live.yaml config --quiet
docker compose --env-file .env.live -f compose.live.yaml up -d --build
docker compose --env-file .env.live -f compose.live.yaml ps

Compose использует реальные сервисы, healthcheck, restart: unless-stopped и четыре
именованных тома. База компаний подключается отдельно только для чтения.
Не выполняйте down --volumes, если нужно сохранить очередь, статьи, карточки и бюджет.
Docker-конфигурация публикует gateway только на 127.0.0.1. Для внешнего сервера ещё
нужны адрес, HTTPS-прокси и авторизация пользователей/компаний; локальный выбор company_id
не является механизмом разграничения доступа.

НАБЛЮДЕНИЕ

/v1/health показывает доступность сервиса. /v1/feeds/status — состояние сбора.
Live-интерфейс показывает очередь, ошибки, карточки и бюджет. /v1/budget на агенте
показывает счётчик расхода; публичный live-статус получает его через gateway.
Health=200 не доказывает свежесть новостей или работоспособность ключа Qwen.
--check проверяет конфигурацию и структуру базы, без модели и проверки оплаты.
Работу полного контура следует проверять на новых статьях, изменениях, дубликатах,
исчерпании бюджета и перезапуске; суточный прогон выполняется отдельно.
