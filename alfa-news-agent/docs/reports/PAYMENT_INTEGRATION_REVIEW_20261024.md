## Найденные проблемы и исправления

| Проблема | Последствие | Исправление |
|---|---|---|
| Совместная схема отставала от нового Python-профиля | `deterministic_rules_v2` отвергался старой схемой; новый вложенный блок не проверялся полноценно | Пересобраны единые JSON Schema/OpenAPI из объединённого генератора. Старые профили без нового блока остаются допустимыми |
| Decimal-суммирование зависело от порядка и глобальной точности | Сумма известных платежей могла оказаться больше общей, неизвестная часть — отрицательной; профиль расходился с графом | Общие точные суммы, доли и сортировка применены в профиле и `PaymentGraph`; регрессии с низкой точностью, большими суммами и перестановкой строк |
| Обещанный scope «без платежей самому себе» обеспечивался только при импорте CSV | Чтение старого/подготовленного отдельно снимка могло включить self-loop | Явное исключение в пути чтения. В исходной базе организаторов таких строк не найдено |
| Python и JavaScript по-разному принимали Unicode-цифры в ОКВЭД | Python мог выпустить отраслевой код, который отвергал Node | Единое ограничение ASCII; неподдерживаемый код остаётся неизвестным |
| JSON Schema проверяла типы, но не согласованность новых агрегатов | Возможны неверный знаменатель, пропавшие суммы, дубли корзин, известная группа без собственной группы | Добавлены одинаковые семантические проверки на Python/Node границах и общие повреждённые тестовые профили |
| Метаданные метода агрегации могли служить основанием AI-вывода | Техническое поле принималось за бизнес-сведения | Для grounding нужны конкретные значения; `method`/`scope` не допускаются как бизнес-факт. Промпты объясняют смысл coverage и групп |
| UI-адаптер `/v1` умножал любой score на 100 | Некалиброванный балл выглядел как процент и получал произвольный приоритет | Сохраняются исходный score и его тип; отображение шкалы и отсутствие ложной вероятности проверяются отдельно |
| Снимок графа не учитывал изменение импортированной арифметики | Старый кеш мог считаться актуальным после изменения helper | В привязку снимка добавлен hash `company_context/io.py`; графы пересчитаны на исходной базе, офлайн-воспроизведение проверено |

Подробные воспроизведения: [расчёт платёжного окружения](PAYMENT_ENVIRONMENT_REVIEW_20261024.md), [контракты и анализ](PAYMENT_CONTEXT_CONTRACT_REVIEW_20261024.md). Новые границы не подтверждают договорную роль, владение или финансовый ущерб: они проверяют согласованность наблюдаемых данных.

## Какой путь приложения проверен

**Для нашей части нужен `/v1` и `RANK_MODE=news-analysis`.** Обычный `/api`, включая главную страницу без включённого адаптера, использует собственный Node Store и обходит Python Data/ML. Стандартный запуск без настройки ранжировщика использует mock. Наличие всех файлов в одной папке не переключает эти режимы автоматически.

После установки зависимостей и сборки, из корня проекта:

```bash
npm run build
RANK_MODE=news-analysis NEWS_MODULE_PATH=. python scripts/dev.py --native-providers --context-db /path/to/companies.sqlite
```

Открыть `/analysis/` для подготовки полного контекста. Лента существующего интерфейса через общий API включается адресом `/?api=v1`. Путь `--context-db` должен вести к существующей базе организаторов. Без `--live` и без ключа внешняя LLM не вызывается; генератор в этом запуске демонстрационный. Настоящими результатами офлайн-проверки являются ранжирование, признаки, контекст и условные Python-советы. Подробный новый платёжный блок доступен в JSON профиля/источника; отдельная визуальная панель coverage не создавалась.

В PowerShell переменные задаются отдельно:

```powershell
$env:RANK_MODE='news-analysis'
$env:NEWS_MODULE_PATH=(Get-Location).Path
python scripts/dev.py --native-providers --context-db C:\path\to\companies.sqlite
```

Обычный smoke теперь явно проверяет сохранение полного нового платёжного блока в источнике анализа, знаменатель с неизвестными контрагентами и версию признаков ручного baseline. Он использует существующие синтетические fixtures, отдельно от проверки реальных данных.

Чистая ветка коллег до объединения: 57 Node-тестов, 87 unittest, 34 pytest прошли; один тест исторического overlay пропущен. Совместный вариант: **105 Node, 151 unittest и 40 pytest прошли**, один pytest для отсутствующего `var/sources/news-analysis` пропущен. Также прошли TypeScript, генерация контрактов, четыре сервиса через HTTP, пять offline-reference сценариев и реальная проверка 30 пар. Skip не относится к внешней LLM. Адаптер и рендер проверены четырьмя VM-регрессиями; Docker и визуальное браузерное ревью не выполнялись.

```bash

Выбрать один подходящий патч и сначала выполнить `git apply --check`. Патчи проверены на чистых соответствующих коммитах. На другой версии репозитория повторно проверить конфликты. Архив не содержит полной базы, оригинальных статей, ключей, окружений и `.git`.

Отдельный признак общей важности общеэкономической новости по-прежнему отсутствует. Новая ветка платёжного окружения этот пробел не закрывает. Его реализация требует отдельного правила масштаба события и проверки качества; в этой работе он не маскируется отраслевыми долями.
