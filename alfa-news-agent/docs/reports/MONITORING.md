# Мониторинг качества: метрики и процесс

> Критерий успеха №12 ТЗ: команда предлагает метрики и процесс регулярного мониторинга качества контента, персонализации и AI-компонентов с учётом обратной связи пользователей и экспертов. Этот документ описывает метрики, источники данных, процесс и пороги. Часть уже реализована (ранжирование, бюджет), часть — план.

## Источники данных
Всё строится на уже существующих артефактах: журнал вызовов LLM (usage, длительность, статус), `self_check.warnings` и `trace` агента, `data_quality.warnings` профиля, лог ошибок с trace ID. Отдельная БД не нужна — достаточно агрегировать логи.

## Обратная связь (пользователи и эксперты)

> ⚙️ **Частично реализовано** в master: адаптивное обучение ранжировщика по обратной связи (`docs/integration/ADAPTIVE_LEARNING.md`, контракты `FeedbackRequest`/`LearningStatusData`, `integration/learning.py`, страница `/learning`). Оценка 0–3 от проверяющего привязывается к `feedback_id` из `/v1/rank`; переобучение идёт фоновыми пакетами; кандидат допускается только при приросте **NDCG@5** на независимом gate-наборе (train/validation/gate 70/15/15 по SHA-256). Ниже — как это ложится в общий процесс мониторинга.

- **Пользователи/проверяющие:** оценка полезности новости 0–3 на `/learning` → в обучение ранжировщика (с защитой: конфликтующие оценки не перезаписываются, gate-группы не входят в fit).
- **Эксперты:** регулярная ручная проверка случайной выборки анализов по чек-листу (разделение факт/банк/AI, обоснованность рисков, отсутствие переуверенных утверждений, корректность цитат). Результаты — в разметку (`docs/LABELING_GUIDE.md`) и в бэклог улучшений.
- Петля: оценки + экспертные замечания → переобучение ранкера с gate-проверкой → переизмерение метрик (`scripts/evaluate_ranking.py`) → доработка правил/промптов.
- ⚠️ Для **отчётного** качества нужен отдельный независимый audit-набор (сами авторы адаптивного обучения это подчёркивают) — рабочий gate-фильтр не заменяет его.

## Процесс и каденс
| Когда | Что |
|---|---|
| На каждый PR, меняющий ранжирование/агента | прогон `evaluate_ranking.py`; метрика не должна падать без обоснования |
| Ежедневно (во время хакатона) | сводка ₽/день, токены, ошибки, провалы валидации |
| Перед демо | экспертная проверка выборки + фиксация известных ограничений |

## Пороги и алерты (предлагаемые)
- Бюджет: ⚠️ при ≥80% от 500 ₽/день, ⛔ при превышении (безопасный отказ).
- Качество: падение nDCG@3 ниже baseline на PR → блок до разбора.
- Надёжность: рост доли провалов валидации/ошибок → ревизия промптов и лимитов токенов.
- Трассируемость: доля выводов без источника > 0 → баг (каждый вывод обязан иметь основание).

## Честные оговорки
- Метрики ранжирования сейчас на маленьком демо-наборе и черновой разметке — число станет защищаемым после независимой разметки (`docs/LABELING_GUIDE.md`).
- Реальная стоимость в рублях зависит от тарифа шлюза (пока плейсхолдер в `model_prices.json`).
- Проверка цитат подтверждает наличие источника, но **не** истинность вывода — отсюда нужна экспертная выборка.
