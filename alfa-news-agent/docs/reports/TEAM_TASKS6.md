# TEAM_TASKS6 — структура, repair и привязки профильных утверждений

Это отчёт подготовительного этапа. После него 25 октября 2026 выполнен согласованный live-прогон (24 вызова); результаты и следующие задачи находятся в REPORT7.md и TEAM_TASKS7.md в этой папке. Ниже «ещё не измерено» относится к состоянию до этого прогона; полная продуктовая приёмка по его итогам также не пройдена.

Ветка: `feature/tasks6-grounding`, база `23945ec`. Входы работы: присланные TEAM_TASKS6, REPORT6 и оригинальный архив `live-llm-merged-20261024.zip`. Новых обращений к LLM не было. Итоговая продуктовая приёмка **не объявляется пройденной**.

## Изменения 1–5

1. В промпте v9 отдельно описаны fact/bank (kind, text, quote, source_ids) и ai (также непустые profile_paths/conditions). У цитат не предлагается создавать пустые необязательные массивы. Для Too few items repair смотрит на конкретный kind и поле текущего черновика: у fact/bank удаление необязательного поля, у ai — заполнение проверенными основаниями. Сам сервер не удаляет и не заполняет поля за модель.
2. Добавлен ориентир 2–5 необходимых claims вместо пересказа всего профиля, с исключением для явно запрошенных профильных сведений. Это инструкция и подсказка, не новый жёсткий лимит или автоматическое усечение. Для Quote source has the wrong evidence kind есть точная инструкция news→fact, bank→bank, профиль→ai. Лимит токенов, настройки модели и максимум двух попыток не изменены. Эффект на реальные длины/обрезку ещё не измерен.
3. Узкие проверки отклоняют формулировки из REPORT6: «отмечен продукт лизинга, что указывает на наличие обязательств» и «внешнеторговая деятельность не ведется». Сохраняются допустимые «отмечен продукт», «договор неизвестен», «нет отметки ФТС», вопросы и явные условия. Проверяются AI-тексты, разделы, заметки и вопросы; дословные fact/bank-цитаты проверяются отдельно и не переписываются.
4. Новый claim-profile-grounding проверяет каждый AI-claim при основном анализе и вопросах. Нельзя спрятать факт в claims при корректном кратком answer. Продуктовые факты требуют своего bank_products-поля, явный has_fts/ФТС — has_fts, платежи — нужного направления. Для распределений требуется статистический лист и его покрытие, для самого покрытия — известная/неизвестная доли того же направления. Существующий resolver, проверка значений и ограничения provenance не заменены.
5. Промпт задаёт точную формулировку для mismatch: «Отрасль компании не совпадает с тематикой новости; возможные косвенные каналы не проверены». Парные тесты принимают её и отклоняют «Прямая отраслевая связь отсутствует». Общего разрешения на отрицание связей по mismatch не добавлено.

Добавлено одно диагностическое правило `Profile claim assertion needs matching profile path`; JSON Schema/OpenAPI пересозданы штатным генератором. Определения Claim, GeneratedAnalysis, GeneratedAnswer, Grounding и Profile **побайтно по JSON-содержимому совпадают с базой**. Новая диагностика не ослабляет выходной контракт.

Старый тест покрытия исправлен по смыслу: его корректный пример теперь описывает выбранную статистику, а не кредитную отметку, подтверждённую только платёжным полем. Проверки неправильных путей и неполного покрытия сохранены.

При ручной проверке пройти выбор компании, анализ, отображение ошибки, источники/страницы и вопросы, смену компании, неизвестные продуктовые флаги и json_schema. Старые ограничения Windows на контрольные суммы CRLF и симлинки полного Python-набора относятся к предыдущему отчёту; здесь выполнен указанный набор из 47 проверок, не заявляется повтор всех Python-тестов.

## Воспроизведение без расходов

```powershell
npm test
npm run typecheck
npm run build
npm run llm:evaluate -- --out var/llm-evaluation/tasks6-offline.json
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe scripts/build_contracts.py --check
.\.venv\Scripts\python.exe -m pytest tests/test_event_interpretation.py tests/integration -q
$env:RANK_MODE = 'news-analysis'
.\.venv\Scripts\python.exe scripts/dev.py --smoke --native-providers
```

В команде llm:evaluate **не указан --live**: код выбирает referenceDraft и execution=offline_reference. API-ключи и исходные данные внешнему провайдеру не отправляются.

Для повторения проверки оригинальных ответов распаковать архив в локальную игнорируемую var-папку и выполнить:

```powershell
node --import tsx scripts/replay_saved_responses.ts --dir var/tasks6-original/live-llm-merged-20261024 --out var/llm-evaluation/tasks6-saved-replay.json
```

Скрипт проверяет MANIFEST, отказывается при несовпадении исходных данных и не исправляет сохранённые ответы. Новая генерация и смысловая приёмка на этих входах остаются отдельным шагом.
