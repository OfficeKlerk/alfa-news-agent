# Draft PR: подготовить Python/Node интеграцию для пяти ролей

> Обновление: для объединённой ветки и переноса всех работ в master используйте [MERGE_TO_MASTER.md](MERGE_TO_MASTER.md) и корневой README. Ниже сохранена инструкция первоначального интеграционного этапа.

**Предлагаемая база:** `feature/node-prototype` (`d1c08bb` на момент аудита).
**Head:** `role5/integration-foundation`.
**Статус:** подготовлено локально; GitHub PR не создан и ветка не опубликована.

В трёх исходных ветках профиль, ранжирование и Node-приложение развиваются отдельно и используют разные JSON-форматы. Этот PR добавляет версионированный `/v1`, чтобы команда могла независимо разрабатывать ML, агента, RAG и UI и проверять общий поток без внешних моделей.

Добавлены JSON Schema/OpenAPI и общие примеры, Python HTTP-адаптер ContextStore/ranker, Node gateway и проверяемые HTTP-клиенты, моки и адаптеры существующих Node-модулей, SDK и технический стенд `/integration`, Compose, workflow Actions, локальный supervisor, контрактные/сквозные тесты и инструкции пяти ролей. Дополнительные источники агента подтверждаются реестром роли 3. Проверенная Python-ветка подключается через read-only overlay из точного SHA после её тестов.

Предметные модули и существующий UI не переписаны. Старый `/api` остаётся совместимым; перевод продуктового UI на `/v1` — отдельная задача роли 4. Ветки не объединены; датасеты Python-ветки не добавлены в этот diff. Старые документы снабжены ссылкой на актуальный ADR интеграции.

Проверено локально: typecheck/build, 28 Node-тестов (включая 18 исходных), 15 новых Python-тестов, 78 тестов точной Python-ветки, HTTP smoke с моками, native-адаптерами и отдельными role-2/role-3 процессами. Compose YAML проверен по официальной схеме. **Docker build/up не проверены из-за отсутствия Docker; workflow Actions ещё не запускался.**

Перед merge нужны Docker smoke и review владельцев 1–4 по контрактам. Ограничения: краткоживущие `/v1` сессии в памяти, текущий snapshot профиля вместо исторического, mock/default-поставщики и лексический native-RAG без дат у исходного OCR-корпуса. Режимы и ограничения указаны в API/документах. Deployment, merge и реальные LLM-вызовы не выполнялись.

Если сначала будет принят Node-прототип в master, нужно перебазировать/перенацелить этот PR и повторить проверки; не включать чужую ветку в master этим инфраструктурным PR незаметно.
