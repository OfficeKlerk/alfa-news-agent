# Публикация готовых результатов в ленте

Основа: master `d49ddc219e55430418d2806dc5c55c0f15cacd7a` от 26.10.2026.

## Правило публикации

Основная лента возвращает только текущую редакцию выбранной компании и роли,
сохранённую вместе с успешно завершённым заданием анализа. Сохранённый ответ
должен совпадать с результатом этого задания и проходить проверку структуры,
ссылок на источники и привязки к компании/новости. Проверка обоснованности по
контексту выполняется движком до сохранения; граница сохранения повторно
проверяет контракт и привязку контекста к роли/компании.

Предыдущая версия больше не подставляется, пока новая редакция ожидает модели,
отложена или завершилась ошибкой. Такие задания, версии и причины остаются в
технических данных: `/v1/live/jobs`, `/v1/live/jobs/{job_id}`,
`/v1/live/analyses/{analysis_id}` и списке версий. Основная лента и избранное
используют одно правило доступности. Некорректная сохранённая строка исключается
индивидуально и не мешает выдаче остальных карточек.

Публикация карточки/ответа и перевод задания в `succeeded` выполняются одной
SQLite-транзакцией. Ошибка валидации или сохранения откатывает эту транзакцию.
История диалога содержит только успешно сохранённые ответы собственных заданий
пользователя; неудачный вопрос не заменяет и не удаляет предыдущие ответы.

## API

Все GET используют `company_id` и `audience_role` (`cfo` по умолчанию).
В `/v1/live/feed` добавлены поля:

| Поле | Смысл |
| --- | --- |
| `items` | Страница доступных проверенных карточек |
| `next_cursor` | Курсор следующей страницы или null |
| `total` | Количество доступных карточек с учётом текущего фильтра избранного, независимо от размера страницы |
| `available_count` | Все доступные карточки выбранной компании и роли |
| `favorites_count` | Доступные карточки в избранном текущего пользователя |
| `visible_ids` | Все ID, доступные в текущем фильтре; интерфейс удаляет недоступные карточки из уже загруженных страниц |
| `running_tasks` | Количество заданий с действующей арендой, владельцем/токеном и актуальной редакцией |
| `has_running_tasks` | `running_tasks > 0` |

`total` и `visible_ids` отражают доступность на момент запроса, включая при чтении
последующих страниц. Сам курсор сохраняет границу публикаций, чтобы новые
карточки не дублировались между страницами. Смена редакции исключает устаревшую
карточку даже по ранее выданному курсору. Курсоры версии 1 необходимо сбросить
и запросить первую страницу заново; новые курсоры имеют версию 2.

`/v1/live/status` возвращает `available_count`, `favorites_count`, `running_tasks`
и `has_running_tasks` на верхнем уровне и в `queue`. `queue.analyses` теперь
означает доступные карточки; прежнее количество всех сохранённых версий доступно
в `queue.saved_versions`. Технические `queue.jobs` сохраняют фактические статусы
заданий, включая истёкшие `running`, до их восстановления worker. Для индикатора
выполнения используйте `has_running_tasks`, а не сумму статусов или включённый
таймер worker. Очередь, отсрочка и неизвестный исход не считаются выполнением.
Вопросы учитываются в выполнении с учётом пользователя; другие роли исключены.

Интерфейс автоматически убирает недоступные карточки после успешного обновления,
сохраняет историю при сбое запроса и показывает ошибки в техническом журнале.
Новые готовые карточки по-прежнему появляются по кнопке «Новые выводы».

## Проверки

Прошли `npm run typecheck`, 495 тестов Node, 257 тестов Python, `npm run build`,
`python scripts/build_contracts.py --check` и офлайн `npm run llm:evaluate`.
Добавлены проверки устаревших редакций между страницами, испорченного результата,
точных счётчиков, изоляции компании/роли/пользователя, истёкшей аренды,
независимости публикаций и сохранности диалога при сбое нового вопроса.
Платные запросы к внешней модели для этих проверок не выполняются.
