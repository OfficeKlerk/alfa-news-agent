# P1: даты банковских документов и проверенные реальные новости

Изменения для роли 3 от master `1793e54`, ветка `feature/rag-bank-metadata`.

## Даты: что подтверждено

Проверены оригинальные PDF, предоставленные с кейсом, а не имена файлов или PDF CreationDate/время загрузки. Первые страницы отрисованы и просмотрены. У обзора золота дополнительно просмотрены все восемь страниц. SHA-256 оригиналов, страница и напечатанная дата записаны в `data/demo/rag/corpus_manifest.json`. Исходные PDF не добавляются обратно в Git.

| Документ | Напечатанная дата | Страница доказательства | OCR-страниц |
|---|---|---|---|
| ALFA-7M26.pdf | 7 сентября 2026 | 1 | 4 |
| ALFA-consumption.pdf | 5 августа 2026 | 1 | 4 |
| ALFA-Macro_Insights-Policy_Rate_11Sep.pdf | 11 сентября 2026 | 1 | 4 |
| ALFA-macro_stat1H26.pdf | 31 июля 2026 | 1 | 5 |
| ALFA_Russian_Steels_1К21PreviewUpdate_15Apr2021.pdf | 15 апреля 2021 | 1 | 4 |
| FI_Strategy_3Q26_22072026.pdf | 22 июля 2026 | 1 | 27 |
| Inflation_tracker_02.pdf | 2 сентября 2026 | 1 | 3 |
| Бонд_Бриф_14092026.pdf | 14 сентября 2026 | 1, нижняя плашка | 5 |
| Gold_digest_August26.pdf | **Не указана** | Проверены 1–8 | 8 |

Итого: **8 подтверждённых дней публикации, 56 датированных страниц из 64**. На обложке золота «АВГУСТ 2026» — отчётный период. На странице 6 уже есть данные, доступные 7 сентября. Поэтому прежняя дата 1 августа была неподтверждённой и удалена. Точный день остаётся неизвестным: этот документ продолжает исключаться из датированного `as_of`-контекста. Для его включения потребуется независимое подтверждение даты от издателя/первичного реестра.

В `data/research.json` к каждой странице добавлены `date`, `publication_date_status`, `publication_date_precision` и ссылка `publication_metadata_id` на запись реестра. У неизвестных дат — `null`; существующий OCR-текст, ID страниц, URL и номера страниц не изменялись. Для контроля исходного OCR в реестре есть хеш последовательности `[page_id,text]` каждого документа.

Store.initialize заново загружает research payload при старте, поэтому метаданные появятся и в существующей базе после перезапуска. Удалять базу не нужно. Существующие фильтры даты и `resolve_sources` сохранены. День без известного времени доступен с консервативной границы `23:59:59.999Z`, а не с выдуманного часа публикации. Это не основание выдавать документ 2021 года за текущую позицию банка.

## Реальные новости

`data/reviewed_news.json` содержит три коротких дословных выдержки из первичных публикаций. Это **выбранные фрагменты, не полные статьи и не AI-пересказы**:

| Издатель | Дата | Первичный URL |
|---|---|---|
| Банк России | 23.10.2026 | https://www.cbr.ru/press/keypr/ |
| АО «СО ЕЭС» | 23.10.2026 | https://www.so-ups.ru/news/press/press-release-view/news/31251/ |
| Минтранс России | 22.10.2026 | https://mintrans.gov.ru/press-center/news/13080 |

Зафиксированы заголовок, буквальный текст, отображённая дата, издатель, URL, день проверки, хеш исходного HTML, хеш выдержки и хеш `[title,url,published,text]`. Время без подтверждённого часового пояса не восстанавливается — используется точность дня. Для ЦБ явно отмечен mutable URL: будущая версия этой страницы не должна молча заменять проверенный снимок 23 октября. Достоверность первоисточника не доказывает применимость события к конкретной компании.

`server/reviewed-news.ts` проверяет набор до записи. Store.initialize устанавливает отсутствующие реальные публикации через тот же saveNews, что используется импортом, в новые и уже существующие базы. Повторный запуск не дублирует записи. Если в базе уже есть публикация с этим URL, она сохраняется: seed не откатывает её на более ранний текст. Последующие редакции импортируются штатным `/v1/news`, а не заменой seed при каждом старте.

Шесть `demo_news.json` остаются отдельными записями с `is_demo=true` и выдаются через `/v1` с `is_mock=true`. Новые публикации имеют `is_demo=false` / `is_mock=false`. Смешанная выдача может иметь общий envelope mode=mock из-за присутствия синтетики — смотреть также пометки каждого события и источника. Demo-профиль компании или тестовый агент не превращаются в реальные из-за настоящего URL новости.

## Проверка

Из корня проекта:

```powershell
npm run typecheck
npm test
npm run build
python scripts/verify_bank_metadata.py
```

Если оригинальные PDF восстановлены в локальной игнорируемой папке:

```powershell
python scripts/verify_bank_metadata.py --pdf-dir data/appendix_2
```

Последняя команда дополнительно сверяет реальные PDF с оригиналами проверки. Хеш подтверждает тождественность файла, а не автоматически доказывает правильность визуального прочтения даты. Проверяющий может открыть указанную страницу и сравнить напечатанную строку.

Целевой тест:

```powershell
node --import tsx --test server/integration/tests/reviewed-corpus.test.ts
```

Покрывает:

- 9 документов/64 страницы, 8 подтверждённых дат/56 страниц; неизвестная дата золота не угадывается.
- Реальный OCR → датированный RAG → точное разрешение того же текста/страницы/URL; будущие и недатированные источники исключены.
- Новый и существующий SQLite → три реальные новости; сохранение demo, повторный импорт, сохранение более поздней редакции.
- Подмена текста/даты/пометки синтетики в reviewed-наборе обнаруживается до импорта.
- Реальные выдержки → HTTP gateway → контекст/ранжирование → live-контракт анализа с точными bank-цитатами. В этом тесте профиль/ранжирование и транспорт LLM подставные, а данные новостей, OCR, SQLite, адаптеры, шлюз и валидаторы настоящие. Внешняя LLM и платный бюджет не используются.

Прохождение теста подтверждает путь и проверку цитат, **не качество внешней модели**. Настоящий live-прогон и экспертная оценка остаются отдельным шагом. Demo-агент остаётся шаблонным и может показать найденные источники без bank-утверждений; роль 3 не меняет генерацию/бизнес-логику роли 2 ради красивого примера.

## Открыть подключённые данные локально

Legacy-приложение: из корня установить `$env:LLM_MODE='demo'`, выполнить `npm start`, открыть http://localhost:8000. При наличии шести прежних demo-записей после запуска добавятся три реальные — база не удаляется.

Общий `/v1`-стенд (нужен Python 3.12 и зависимости по корневому README):

```powershell
npm run build
python scripts/dev.py --native-providers --data-dir data
```

Открыть http://localhost:8000/analysis/. Здесь retrieval использует настоящий локальный корпус и reviewed-набор, генерация остаётся demo. Стандартный запуск без `--native-providers --data-dir data` сохраняет прежние моки/fixtures, намеренно не выдавая их за реальные источники. Для live следовать LIVE_LLM.md и отдельно согласовать расходы.

Обновлён Dockerfile.node: reviewed-набор включён в образ вместе с корпусом. Ключи, SQLite, полный HTML и PDF в PR не входят. `data/manifest.json` пересчитан под фактические файлы; исходные CSV gzip в чистом клоне остаются крошечной синтетикой.
